# 《老街品牌局》内容圣经 v1.0.0

本文件是内容生产与审核的共同约束。它解释“为什么这样写”，不替代机器可校验的 `GameContent` 内容包。

## 1. 故事边界

- 场景：屯溪老街的一间虚构茶饮店，使用“真实经营问题 + 虚构品牌事件”的组合。
- 教学目标：让玩家感受到品牌不是 Logo 单项作业，而是研究、产品、命名、定位、IP、包装、关系网络和组织执行共同形成的系统。
- 现实尺度：事件可以有轻微整活和反差，但必须能回到客流、预算、交付、信任、渠道或文化表达的现实机制。
- 文化边界：不把徽州文化、老街居民或地方生活当成廉价笑点；不虚构可被误认为史实的具体历史断言。涉及历史或地方知识时，必须在教师版内容字典中标明“事实 / 虚构 / 教学化简”。

## 2. 角色关系

| 角色   | 经营位置         | 主要关切                               |
| ------ | ---------------- | -------------------------------------- |
| 你     | 品牌发起人       | 在有限预算里做出能继续经营的品牌       |
| 许房东 | 铺面房东         | 老街热闹，但不希望短期网红破坏街区秩序 |
| 阿禾   | 店员与现场观察者 | 承诺不能超过每天真正做得到的工作       |
| 老周   | 原料供应商       | 愿意试，但需要稳定、可预测的订单       |
| 小满   | 视觉设计师       | 视觉系统要离开效果图进入每个触点       |
| 豆花   | IP 插画师        | 角色要承担识别、叙事或关系任务         |
| 陈姨   | 附近老客         | 品牌不能只为游客服务而忘记邻里日常     |
| 小沈   | 本地摄影者       | 愿意分享真实街区，不替品牌说假话       |
| 周经理 | 平台合作经理     | 希望一次漂亮的增长证明合作价值         |

角色不是“正确答案提示器”。对话只提供立场和摩擦，玩家仍需结合证据、资源与后果作决定。

## 3. 语气与表达

- 游戏内文字先保证自然、短句和可扫读，再加入轻松幽默；一张卡只承担一个动作或一个判断。
- 可以出现“先别急着做 Logo”“效果图过了，现实还没过”这类口语化提醒，但不能用生硬的术语堆叠制造难度。
- `Logo`、`IP`、`VI`、`包装` 等课程和专业词汇保留原称；首次出现时用一句白话说明其在当前经营场景中的任务。
- 不用“前后矛盾会产生真实代价”这类抽象警告，改写为“这次省下的钱，可能会在后面的返工和解释里花回来”。
- 结果反馈遵循“现在发生 / 先记在账上 / 之后验证”三层，不直接宣布标准答案。

## 4. 12 轮知识地图

| 章节           | 轮次    | 操作主题               | 玩家要经历的关键取舍                 |
| -------------- | ------- | ---------------------- | ------------------------------------ |
| 认识顾客与产品 | r01–r04 | 人群、研究、概念、命名 | 先理解谁，再决定卖什么、承诺什么     |
| 定位与视觉     | r05–r08 | 交付、定位、IP、VI     | 让定位进入产品、价格、空间和视觉触点 |
| 离店与传播     | r09–r10 | 包装、社群、平台       | 选择传播扩张速度，以及谁来解释品牌   |
| 系统与持续经营 | r11–r12 | 运营摩擦、品牌原则     | 在增长、信任、现金和组织能力之间收束 |

每轮至少有一条证据、两个以上可执行选择、即时效果和延迟效果；知识点必须通过资源取舍或可观察后果被操作，而不能只停留在角色对白中。

## 5. 事件审核规则

每个事件必须记录触发条件、概率、唯一性、班级范围、效果理论和解释。审核时逐项回答：

1. 玩家过去的哪个决定让它有机会发生？
2. 事件改变了什么经营机制，而不是只增加一个随机惩罚？
3. 玩家能在报告中看到“做了什么—改变了什么—为什么—何时显现”？
4. 轻幽默是否仍然尊重当地生活、学生和经营参与者？

事件可制造意外，但不使用完全超现实的魔法、凭空改变规则或教师临场判美。

## 6. 视觉系统审核规则

六套视觉系统在统一的店招、杯套、包装、头像触点中比较。比较维度为识别、缩小可读性、同街差异化、包装耐用性、文化可信度、品牌一致性、触点适配和生产成本。视觉测试由结构化属性和规则结算，不能由运行时 AI 或教师临场判断。

“好看”不是结算维度；视觉方案必须说明它更适合什么品牌承诺、在哪些触点容易失效，以及一次有限修订应优先解决什么现实问题。
