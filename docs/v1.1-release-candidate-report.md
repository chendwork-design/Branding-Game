## 3. 浏览器矩阵

2026-08-27 使用独立端口运行：`WEB_PORT=4176`、`API_PORT=3000`、`V11_API_PORT=3004`，避免复用旧服务；Chromium 11/11 通过，iPhone WebKit 的 11 个测试按 spec 独立启动后 11/11 通过。测试覆盖加入、旧版兼容页、断网恢复、教师端、四轮切片、十二轮内容、服务端逐轮结算、报告和刷新恢复。

说明：在同一进程连续运行全部 WebKit spec 时曾出现环境资源串扰，表现为已经渲染的按钮无法在默认时限内稳定点击；将每个 spec 放在干净浏览器/服务进程中复验后全部通过。该现象应在正式发布机上再次观察，但不改变应用功能断言。

测试期间发现并修复一个真实的预览问题：Windows 上残留的 3000 端口 Node 服务被 Playwright 复用，旧服务没有允许 4174 的 CORS 响应，浏览器因此显示 `Failed to fetch` 或白屏。现在测试启动配置会按端口传入 `CORS_ORIGINS`，并且发布/测试前必须确认目标端口没有残留服务。

## 4. 尚未能在当前环境代替完成的发布门禁

以下项目不能用浏览器模拟或自动化结果冒充完成：

1. 真实 iPhone Safari、真实 Android Chrome、微信内置浏览器的现场测试；
2. 8—12 名学生的平衡试玩、35—50 分钟中位时长和路线辨识记录；
3. 课程负责人对 12 轮文案、地域文化、理论因果和视觉方向的签字；
4. 真实生产部署、HTTPS、校园网络和 80 名学生同时访问的完整发布演练；
5. 生产数据库备份、恢复和学生数据保留期的运维确认。
