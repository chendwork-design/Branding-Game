## 必须由人完成的门禁

以下四项统一填写在 [v1.2 人工发布验收记录](v1.2-人工发布验收记录.md)，不得继续使用 v1.1 表单冒充本版本验收。

> 组织试玩已按项目负责人决定取消，不作为本版本放行阻断项；因此 A 项标记为“本版不执行”，其未知风险必须随候选包封存。B—D 仍是内容终审、目标设备和正式部署环境的工程门禁。

### A. 两名未修读本课的学生首局试玩（本版不执行）

本版本不组织该项试玩，不填入虚构结果；以下问题仅保留为后续版本的反馈模板：

1. 这一轮发生了什么？
2. 你当前要决定什么？
3. 你花自由行动力后得到了什么，它帮助比较了哪项方案？
4. 你为什么选择或跳过该方案？
5. 结果让谁发生了什么变化？
6. 你能否在 R05 说出 LOGO、VI、IP 分别在这局里承担什么？

通过条件：关键任务理解率 100%，首次术语解释可找到率 100%，比较对象识别率至少 90%，不存在后台术语暴露或规则性误解。

### B. 课程负责人内容终审

按 [v1.2 人工发布验收记录](v1.2-人工发布验收记录.md) 的十二轮表逐轮朗读和签核；特别复核屯溪老街、地方茶、价格基准、幽默事件的现实边界，以及视觉方案不能被误认为最终作业范例。

### C. 真机与校园网络

在真实 iPhone Safari、Android Chrome 和微信内置浏览器分别完成：加入班级、R05 名称和术语、R08 视觉比较、一次 R09 包装测试、结果页、刷新恢复。记录设备型号、系统、浏览器、网络、失败截图与匿名 playthrough ID。

### D. 正式班级 80 人演练

在目标 HTTPS 域名和校园网络下，于 5 分钟内让 80 个测试身份加入，至少 40 个并发动作；同时抽查教师总览、实名时间线、匿名案例、四类 CSV、关闭班级、备份、恢复与重放。

## 发布前命令

```powershell
pnpm content:compile
pnpm release:check
pnpm lint
pnpm typecheck
pnpm test
pnpm release:check:v11
pnpm build
pnpm release:build
pnpm release:smoke
pnpm assets:check:v11
pnpm assets:audit:v18
pnpm pilot:preflight
pnpm image:build
```

其中 `release:build` 会生成可由纯 Node 启动的 API 运行目录，`release:smoke` 会校验
`/ready`、内容版本和内容校验和；`image:build` 必须在目标 Docker 环境执行并记录镜像摘要。
本机若未安装 Docker，只能记录为“待目标环境执行”，不能把镜像门标记为通过。

完成 B—D 后，连同“A 项按产品决策未执行”的风险声明，将测试日期、审查人、设备矩阵、内容包校验和、班级种子与构建产物一起封存；之后只创建绑定 `v1.2.0` 的新班级，不编辑已发布班级的内容或结果。
