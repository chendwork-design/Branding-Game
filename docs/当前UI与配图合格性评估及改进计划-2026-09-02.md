# 老街品牌局：当前 UI 与配图合格性评估及改进计划

日期：2026-09-02  
评估范围：学生端 `/v11` 全流程、移动端与桌面端布局、主要弹层和经营看板、当前运行时配图、视觉方案比较、教师端源码结构、线上内容与本地内容一致性。  
评估依据：现有 PRD、项目开发规则、`game-ui-ux` 对响应式布局、操作连续性、焦点管理与状态恢复的要求，以及此前确认的品牌视觉目标。

## 一、结论

**当前项目属于“可以继续内部试玩，但不适合作为正式课堂发布版或视觉冻结版”。综合合格度约 66/100。**

它已经具备完整的经营回合骨架，首轮引导、调查回溯、选择详情、收益反馈、章节复盘和新版场景图都有明显进步；但仍有四类会直接破坏正式体验的问题：

1. 线上 API 仍在提供旧的内存内容，和本地已编译内容不一致，导致第 8 回合视觉方案选择后检查器为空，属于流程阻断风险。
2. 移动端若干关键页面明显超过“一屏理解、短滚动决策”的目标；桌面端仍是居中的窄单列，没有使用可用空间。
3. 经营看板、选择详情等弹层关闭后不能稳定恢复原操作位置；从选择页打开看板再关闭，会退回调查页，流程上下文丢失。
4. 新配图单张质量提升明显，但视觉方案比较尺寸过小、三案构图条件不一致，且运行时仍存在跨回合重复图和“同底图轻微改色”的结果图。

因此，当前版本的主要矛盾已不再是“缺页面”，而是**发布一致性、操作连续性、信息密度和配图作为决策信息的有效性**。

## 三、已经达到目标的部分

### 1. 首轮与简报的叙事方向正确

开场已经能说明玩家角色、经营目标和失败风险。新版第 4、5、6、9、10、12 回合简报图与经营问题之间有清楚的语义关系，比直接复用参考图或无关品牌板更接近“现场证据”。

### 2. 调查卡已经形成可回溯信息

调查过的事项会进入“已经查到的事”，可以收起和重新查看，且不会重复扣除调查资源。“问十位附近住户”等此前缺失结果的问题在本地完整流程中已能看到。

### 3. 选择详情具备真正的决策信息

方案详情已包含成本、收益、风险、证据关联、预测与风险计划，不再只是装饰性文案。状态颜色同时有文字标签，不完全依赖颜色表达。

### 4. 经营看板的基础可用性较好

看板标题区保持在顶部，关闭按钮不会随内容滚走；大字模式和减少动效开关有效，390px 宽度下未观察到横向溢出。

### 5. 新三案视觉本身具备品牌完成度

“一笔成街”“山影入杯”“茶友阿街 IP”的配色、材质和环境统一度较高，没有明显乱码或结构错误。问题主要发生在比较机制和应用一致性，而不是单张画面质量。

## 四、未达标问题与原因

### P0：线上内容与本地内容不一致，视觉选择链路会失效

线上 `GET /api/v11/content` 返回的版本名称虽然为 `v1.2.0`，但第 8 回合所有方案的 `visualRouteId` 为空；本地 `content/compiled/v1.2.0.json` 中则已经包含 `v-line`、`v-symbol`、`v-hand`。因此线上选择视觉方案后只显示“已选择”，视觉检查器仍为空。

根因不是按钮样式，而是服务端仍持有旧的内存内容。仅刷新前端无法解决。直接重启服务可能清除当前内存试玩记录，所以本次评估没有擅自重启。

### P0：操作子步骤没有进入正式流程状态

当前新版行动中心内部用组件局部状态保存“调查 / 方案”子步骤。打开经营看板会切换页面栈；关闭后组件重新挂载，局部状态恢复为初始调查页。玩家会感觉自己被退回上一流程，严重时会误判为卡死。

这说明页面栈管理了“大页面”，但没有管理关键子步骤、展开证据和返回焦点。

### P0：弹层焦点没有恢复到发起操作

弹层打开时能把焦点放到关闭按钮，也能用 Esc 关闭；但关闭后焦点落到 `body`，不是原来的“查看详情”或“看店铺状态”按钮。键盘用户会失去当前位置，移动端也可能出现滚动位置和上下文错觉。

### P1：关键页面滚动过长

实测 390×844：

- 首轮简报约 1.74 个视口；首屏同时出现 6 个概念入口，且术语解释自动展开，主要行动按钮被推到下方。
- 行动中心约 1.74 个视口。
- 方案列表约 2.12 个视口；成本、证据、风险和补充说明同时堆在列表卡片里。

根因是“列表负责概览”和“详情负责判断”的边界仍不清楚。页面把所有正确的信息都放了进去，却没有控制每一步真正需要看到的信息量。

### P1：桌面端没有真正使用桌面布局

1366×768 下，外壳接近全宽，但主要经营区域仍约 780px 居中，页面高度仍超过 1200px。代码里存在双栏相关样式和旧版结构，但当前实际渲染的 `ActionCenterV14` 没有接入该布局。

### P1：结果页的视觉奖励不足

结果图目前只是标题右侧约 80×80 的缩略图。它没有占据结果页上部 35%–40% 的视觉空间，无法让玩家一眼看到“我的决定使门店发生了什么”。收入文字存在，但画面反馈仍弱，降低了经营收益的激励感。

### P1：视觉方案比较不公平，也不易看清

在移动端，三张近 3MB 的大图最后只显示为约 68–86px 的缩略图，细节无法参与决策。三案还使用了不同镜头和载体：有的强调门店，有的强调杯具，有的让 IP 占据半张画面。玩家比较到的既是系统风格，也是摄影构图和物料数量，不能公平判断哪套视觉系统更适合当前承诺。

此外，卡片使用的是位图中的设计语言，实际触点检查器使用另一套 SVG 标记，预览与应用结果并非同一系统。

### P1：资产过重，现有审计未覆盖新增图片

当前检查结果：

- `visual-system-ip.png`：约 2.996MB
- `visual-system-line.png`：约 2.896MB
- `visual-system-symbol.png`：约 2.786MB
- `apps/web/public/assets/v11` 中图片/矢量资源合计约 34.25MB

现有 `check-v11-assets.mjs` 因总量超限而失败。`audit-visual-assets.mjs` 虽然通过，但它的清单没有包含三张新 VI 图和六张新简报图，当前绿色结果不能代表全部运行时资产合格。

### P2：结果图仍有重复和弱差异

运行时资产中发现多组完全或近似重复：第 2 与第 10 回合的稳定/吃紧/危机图完全重复；部分简报图与结果图或章节图复用；第 8、9 等回合不同经营状态之间只有轻微色调差异。

同一个机位可以保留，但结果必须呈现可辨认的经营事件差异，例如客流、排队、陈列、员工动作、库存、外带包材和顾客表情，而不能只做滤镜变化。

### 教师端说明

教师端源码已包含登录、班级切换、分析、导出、学生时间线和匿名案例，且匿名投影与姓名学号视图有分离。由于本次没有教师账号，也没有授权执行登录或导出，结论仅为“结构基本完整，尚未完成真实课堂操作验证”，不计为当前 P0 阻断。

## 五、精简改进计划

本计划只修复已发现的有效问题，不新增独立演示页、重复测试框架或装饰性内容。

### 第一批：打通正式流程（P0）

1. **校准线上内容版本**
   - 在保留或导出当前内存试玩记录后，重启 API，使其加载当前 `content/compiled/v1.2.0.json`。
   - 在现有发布检查中比较线上内容校验值与编译文件校验值，并校验第 8 回合 `visualRouteId` 非空。
   - 验收：三套视觉路线均能打开对应检查器、完成预选、返回详情并提交回合。

2. **把行动中心子步骤纳入流程状态**
   - 将“调查 / 方案”步骤、展开的调查结果和返回位置存入屏幕状态或检查点，不再只放在组件局部状态。
   - 验收：从方案页打开/关闭看板、刷新或返回后仍停留在原步骤，资源和选择不重复结算。

3. **统一弹层焦点管理**
   - 在现有 `useDialogFocus` 中记录打开前的触发元素，关闭后恢复焦点；看板、方案详情、视觉检查器共用。
   - 验收：Tab 不逃出弹层，Esc 可关闭，关闭后焦点回到原按钮。

### 第二批：提高信息效率与响应式质量（P1）

4. **压缩移动端普通页面**
   - 简报只展示 1–2 个本轮关键概念，不自动弹出术语卡；其余概念通过“查看本轮术语”展开。
   - 方案列表只保留标题、核心承诺、成本/时间和最关键证据；收益、风险与预测放到详情。
   - 验收：390×844 下普通简报、行动页和方案概览接近 1.2 个视口，主按钮无需盲目滚动即可发现。

5. **启用真正的桌面双栏**
   - ≥900px 时左侧显示调查/方案列表，右侧显示选中项详情或现场证据；移动端继续使用底部详情层。
   - 验收：1366×768 不再是 780px 窄单列，主要选择与详情可同时看见。

6. **重构结果页视觉层级**
   - 使用 16:9 结果场景占页面上部约 35%–40%；收入图、现金变化和关键指标紧随其后，继续按钮保持可发现。
   - 收入图只显示金币/收款动作，不在图片中生成数字；具体 `+¥xxx` 由界面文字动态呈现。
   - 验收：玩家无需阅读整页即可说出“发生了什么、赚/亏多少、为什么”。

### 第三批：重做视觉比较与资产交付（P1）

7. **按同一比较模板重制三方案**
   - 三案统一机位、门店/杯/袋三类触点、品牌名称区域、画面比例和光照；只改变线条、符号、字体、基础色和 IP 规则。
   - 移动端使用可左右切换的大图或 3:2 大卡，不再用微型缩略图承担主要比较。
   - 卡片和检查器共用同一套 SVG 标记、色板和动态品牌名；位图只负责中性场景和材质氛围。
   - 验收：玩家比较的是视觉系统，而不是不同摄影构图；选择后实际触点与预览一致。

8. **压缩并补齐资产清单**
   - 三张 VI 图和六张新简报图输出响应式 WebP/AVIF，保留必要 PNG 原稿但不直接进入首屏。
   - 扩充现有资产清单，使所有运行时引用文件都具备尺寸、来源、用途和审核状态；直接改进现有两个检查脚本，不再增加第三套审计。
   - 验收：关键首屏单资源不超过 1.5MB，常用首轮缓存不超过 20MB，运行时引用覆盖率 100%。

### 第四批：清理重复结果图（P2）

9. **优先处理第 2、4、6、7、9、10 回合结果图及第 3 章章节图**
   - 删除跨回合完全重复图。
   - 保留同机位时，为稳定/吃紧/危机分别加入明确的客流、服务、库存、陈列或顾客反应差异。
   - 验收：不看状态文字也能判断三种结果的方向，且图片与当轮问题直接相关。

10. **最后做一次教师端真实操作核验**
    - 只验证登录、班级切换、学生时间线、匿名投影和导出，不增加教师端新功能。

## 六、统一验收门

完成上述改造后，只使用现有测试体系并为每个真实缺陷补一条针对性回归，不新增冗余截图测试：

- 线上 API 校验值与当前编译内容一致，第 8 回合视觉路线完整。
- 390×844 无横向溢出，普通关键页面接近 1.2 个视口，主行动可发现。
- 1366×768 使用列表—详情双栏。
- 所有主要弹层都能保持焦点、Esc 关闭并恢复触发位置。
- 视觉三案使用相同触点和构图模板，卡片预览与实际检查器一致。
- 所有运行时图片进入资产清单，不再存在跨回合完全重复的结果图。
- 收益、成本、时间、指标和结果图由服务端结算结果驱动，客户端不自行计算。
- 现有 lint、typecheck、内容测试、规则引擎测试、API 测试和 Web 全流程测试继续通过。
