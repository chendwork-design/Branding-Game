# 《老街品牌局》游戏流程与机制升级修改文档 v1.2

> 文档性质：游戏文本之外的流程、机制、界面状态、规则引擎、视觉玩法、反馈、激励、教师分析与验收规格  
> 配套文档：`docs/游戏文本全面升级指导-v1.2.md`  
> 基线版本：PRD v1.1 与当前 `v1.1.0` 发布候选  
> 目标：把当前“可以完整走通的教学页面”升级为“因果清楚、资源取舍成立、能独立玩完、值得复盘的轻量剧情经营游戏”。

## 1. 文档边界与已确认结论

本文不重复规定具体中文措辞。术语解释、口语化、主动语态、后台信息隔离和逐轮文本改写，全部以《游戏文本全面升级指导 v1.2》为准。

本文处理以下问题：

- 每轮怎样开始、怎样推进、怎样结束；
- 玩家怎样使用行动力，不会把自己卡死；
- 行动、调查、情报与战略选择怎样形成真实因果；
- 哪些回合可以跳过战略选择，跳过究竟意味着什么；
- 经营指标怎样让玩家一眼看懂“够不够用”；
- 品牌名、LOGO、VI、IP 和包装怎样形成可操作的视觉玩法；
- 结果反馈、突发事件、成就和章节进度怎样提供即时激励；
- 手机端怎样避免长页面和调查问卷感；
- 教师怎样获得完整决策过程，但不能修改已发布内容或操纵结果；
- 规则、数据、测试和发布怎样支撑以上体验。

以下结论已经确认，不再作为开放问题：

1. 游戏为手机竖屏优先的独立页游，学生课下独立完成，首局目标时长 35—50 分钟。
2. 整局模拟屯溪老街茶饮品牌一年的创建与经营，共四章十二轮。
3. 学生自行填写品牌名；名称评价不调用 AI 或外部 API。
4. 学生输入学号和姓名，教师可查看实名决策过程；匿名课堂展示不得包含姓名和学号。
5. 教师发布班级后不能修改内容、权重、结算、事件、奖励或学生结果。
6. R01、R02、R03、R04、R05、R08、R12 必须完成战略选择。
7. R06、R07、R09、R10、R11 可以选择“跳过本轮战略选择”；跳过即直接结算本轮，不是暂缓。
8. 调查只辅助判断和改变有限结果权重，不解锁隐藏的“正确选项”。
9. IP 是可选品牌路线，不要求每名玩家都建立 IP。
10. 最终胜负不是“现金最多”；经营生存、顾客资产、品牌资产和系统一致性共同决定经营等级。

## 2. 当前实现审计

### 2.1 已经具备的可复用基础

当前版本已经有：

- 12 轮内容、60 个战略方案、确定性规则引擎和服务端结算；
- 现金、行动力、时间、经营账本、即时效果和延迟效果；
- 行动、情报、战略方案、风险预案、视觉测试和结果页；
- 四维综合评价、路线称号、报告、教师时间线、匿名案例和 CSV；
- 首局不可覆盖、刷新恢复、重玩隔离、80 人 API 演练和确定性模拟；
- 手机页面状态栈、焦点锁定、文字放大与减少动效。

因此本轮不是推倒重写。应保留确定性引擎、内容版本绑定、追加式日志、报告证据链和教师只读边界，在其上升级核心循环。

### 2.2 当前最重要的机制缺口

| 缺口                       | 当前直接证据                                                                    | 玩家体验后果                                                 |
| -------------------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| 行动力没有战略保底         | 每轮只有一个 `stageActionPoints=6`；行动、情报、测试、预案和战略选择共用同一池  | 玩家查看或行动后可能没有足够行动力执行任何战略方案           |
| 没有跳过战略选择动作       | 现有动作协议和 UI 中不存在 `choice_skipped`                                     | 可跳过回合的产品决定尚未落地，流程只能强迫提交方案           |
| 行动与情报互相割裂         | `V11StageAction` 只有成本和描述，不产生结构化结果；`V11Evidence` 又单独扣行动力 | 玩家感觉行动只是空耗资源，情报则像另一张付费清单             |
| 同一调查可能被重复收费     | 行动和查看情报各自调用 `spend()`                                                | “做调查”和“看调查结果”没有统一成一次真实经营行为             |
| 选择与情报连接只停在标签   | 详情页主要显示情报标题是否已查看                                                | 玩家看不出哪条事实支持哪个方案、支持哪一部分、还留下什么未知 |
| 指标只有数字               | 经营看板显示数值和一句解释，没有进度区间、需求阈值或容量余量                    | 例如“交付能力 62”无法判断当前是否够用                        |
| 结果美术仍是通用占位       | 资产清单有 88 个键，但当前正式目录只有 1 个占位文件；结果页使用通用杯子图形     | 玩家操作后看不到店铺、顾客或视觉触点发生真实变化             |
| 视觉方案差异主要靠文字     | 6 套视觉系统有数值和描述，但没有完整 LOGO、IP、包装和触点示意                   | 视觉题仍接近阅读选择题，不能形成课程需要的感性认识           |
| 品牌名输入尚未进入状态     | 当前 Schema 与学生流程没有 `brandName` 或命名意图                               | “学生自行命名”没有影响后续店招、包装和报告                   |
| 过程激励不足               | 正式内容只有 2 个成就、3 个结局；没有章节体检状态                               | 十二轮容易变成重复的“读—选—看加减分”                         |
| 关键判断机制没有完成       | 状态中保留 `predictions`，但学生流程没有轻量的关键轮预测交互                    | 原“执行前判断”的教学价值和即时奖励都没有实现                 |
| 当前追踪表高估了体验完成度 | 多项需求标记为自动化已实现，但真人试玩、正式视觉资产和中文终审仍未完成          | 结构可运行不能等同于流程好玩、易懂或可发布                   |

### 2.3 设计诊断

从游戏设计角度看，当前主要问题不是规则数量少，而是 MDA 三层没有完全接上：

- 机制层有现金、行动力、情报、选择和指标；
- 动态层却没有稳定形成“我为回答一个问题采取行动，再据此押注一条路线”；
- 体验层因此容易变成调查问卷，而不是经营中的紧张、发现、掌控和成就。

升级目标不是增加更多按钮，而是让每一个按钮进入同一条闭环：

> 现场问题 → 分配有限资源 → 得到具体信息或准备 → 比较现实方案 → 承担选择 → 看见世界改变 → 带着新状态进入下一轮。

## 3. 目标核心循环

### 3.1 整局结构

```text
加入班级
  ↓
序章：身份、目标、资源、赢法
  ↓
第一章：先决定为谁服务（R01—R02）
  ↓ 章节体检
第二章：产品、价格与品牌身份（R03—R06）
  ↓ 章节体检
第三章：服务、视觉与顾客关系（R07—R09）
  ↓ 章节体检
第四章：增长、危机与下一年（R10—R12）
  ↓
年度结局：经营等级 + 路线称号 + 因果报告 + 课堂问题
```

章节结束点固定为 R02、R06、R09、R12，与当前内容包的 `chapterId` 一致。

### 3.2 单轮状态流

```text
roundBrief
  │ 已知现场、当前目标、本轮两难、时间节点
  ▼
questionBoard
  │ 2—3 个本轮必须判断的问题
  │ 免费已知事实 + 可付费行动
  ▼
actionOutcomeSheet
  │ 调查得到证据 / 准备改变条件 / 询价缩小成本不确定性
  ▼
choiceList
  │ 所有战略方案始终可见
  ▼
choiceDetail
  │ 成本、收益、风险、工作量、情报关系、可选预案
  ├─ visualCompare（R05/R08/R09 按需要）
  ├─ keyPrediction（仅关键轮，一次点击）
  ├─ commitChoice
  └─ skipChoice（只在允许跳过的回合）
  ▼
roundResult
  │ 图像/短动效、人物反应、顾客变化、店铺变化、账本变化
  ▼
下一轮 / 章节体检 / 年度结局
```

### 3.3 单轮时长目标

| 环节           | 目标时长 | 设计要求                              |
| -------------- | -------: | ------------------------------------- |
| 看懂现场与目标 | 20—35 秒 | 首屏直接说明冲突，不先读理论          |
| 分配自由行动力 | 30—75 秒 | 最多 2—3 个问题组，不展示两套重复清单 |
| 比较战略方案   | 30—60 秒 | 摘要短、详情按需打开、支持来回比较    |
| 预案或关键判断 |  0—15 秒 | 普通轮不强制；关键判断只点一次        |
| 结果反馈       | 15—30 秒 | 先看世界变化，再看数值和理论          |
| 单轮总计       | 2—4 分钟 | 不把理论报告塞入单轮主流程            |

## 4. 流程与机制升级需求

### 4.1 双层行动力与推进保底

每轮提供总计 8 点行动力，但拆成两个不可互换的池：

| 资源       | 默认值 | 用途                                             | 是否跨轮 |
| ---------- | -----: | ------------------------------------------------ | -------- |
| 自由行动力 |   4 AP | 调查、观察、询价、测试、谈判、风险预案、视觉测试 | 否       |
| 战略行动力 |   4 AP | 执行一次战略方案；方案本身消耗 2—4 AP            | 否       |

规则：

1. 自由行动不能消耗战略行动力。
2. 战略方案按内容分别消耗 2—4 点战略行动力；成本差异必须对应更高的范围、工作量或风险。
3. 仍需用现金、准备天数、工作量、风险和后果解释差异，不能只用 AP 制造假复杂度。
4. 风险预案消耗自由行动力和/或现金，必须在提交战略方案前配置。
5. 视觉测试消耗自由行动力；选择视觉方案本身不额外消耗战略行动力。
6. 两类行动力均不跨轮，不兑换现金，不影响最终得分。

#### 行动力预警

- 自由行动力从 2 降至 1 时，显示一次轻提示；
- 自由行动力即将归零时，执行按钮弹出确认卡；
- 提示必须明确“战略行动力已经保留，仍可推进”；
- 若行动成本超过当前自由行动力，按钮禁用并说明差多少；
- 禁止只用灰色表达不可操作状态。

#### 现金死局保底

必须完成战略选择的回合，至少有一项“保守维持”方案满足：

- 现金成本不高于玩家在所有合法前置路径中的最低可达现金；
- 方案按其内容消耗 2—4 点战略行动力；保守方案也必须保留真实机会成本。
- 仍有真实机会成本或增长损失，不能成为免费最优解。

这样保证玩家不会因为前几轮现金不足而无法完成课程核心回合。

#### 建设路径

- 状态新增 `freeActionPoints` 与 `strategyActionPoints`；旧 `stageActionPoints` 只用于 v1.1 历史回放。
- 内容 Schema 将行动成本拆成 `freeActionPointCost` 与固定战略成本规则。
- 引擎增加 `canExecuteAction`、`canCommitChoice` 和 `getRoundExitOptions` 纯函数。
- UI 在每次动作前调用服务端或共享规则的预检结果，不能自行猜测余额。

#### 验收

- 任意合法状态都至少存在“执行一个战略方案”或“允许跳过”的离开路径；
- 10,000 局随机合法行动模拟不存在无法推进状态；
- 自由行动力归零后仍能完成本轮战略选择；
- 不允许自由行动透支战略行动力。

### 4.2 “跳过本轮战略选择”机制

允许跳过的回合：R06、R07、R09、R10、R11。

不允许跳过的回合：R01、R02、R03、R04、R05、R08、R12。这些回合承担课程核心结构：客群、定位、产品、价格、身份、视觉系统和年度方向必须形成明确决定。

#### 跳过的准确含义

- 直接结束本轮战略选择，不是暂缓；
- 不执行任何新战略方案；
- 不退还此前花在调查、测试或预案上的资源；
- 不消耗战略行动力，但未使用的战略行动力随本轮结束作废；
- 本轮仍结算固定成本、基础经营收入、已到期延迟效果和符合条件的公共事件；
- 不获得方案即时收益，也不承担该方案的直接成本；
- 可能承担“错过机会、问题未处理、维持现状”的自然后果，但不能额外偷偷施加惩罚；
- 报告记录 `choice_skipped`，明确区分“主动不做”与“操作失败”。

#### 交互

跳过入口放在所有方案之后，视觉层级低于主要执行按钮，但不能隐藏在折叠区。点击后出现一次确认：

- 告知本轮会直接结算；
- 告知已花资源不会退还；
- 告知本轮不会执行新方案；
- 提供“继续比较”和“确认跳过”。

#### 建设路径

- 动作协议新增 `choice_skipped`；
- `V11Round` 新增 `skipPolicy: 'forbidden' | 'allowed'`；
- 结果类型支持 `resultType: 'choice' | 'skip'`；
- 报告和教师时间线增加跳过原因、前置行动和自然后果；
- 成就、路线统计和正式决策数不得把跳过伪装成普通方案。

#### 验收

- 只在指定五轮显示跳过；
- 跳过后直接进入结果页，不回到选择页；
- 跳过不会返还自由行动力、现金或时间；
- 跳过路径可完成整局并生成完整报告；
- 教师可区分“未进入该轮、页面退出、主动跳过”。

### 4.3 按“决策问题”重构行动与情报

当前“可以做什么”和“可选信息”不应继续作为两套并列清单。新结构以本轮需要回答的 2—3 个问题为容器。

每个问题组包含：

1. 免费已知事实：角色、现场或公开数据已经告诉玩家的内容；
2. 可选行动：玩家可以花自由行动力进一步调查、测试或准备；
3. 行动产出：执行后得到证据、成本范围、能力变化或风险缓冲；
4. 关联方案：它主要帮助比较哪些战略方向；
5. 剩余未知：行动完成后仍不能确定什么。

#### 三类行动必须分清

| 行动类型  | 玩家实际做什么                     | 结构化产出                                    | 是否直接改指标                         |
| --------- | ---------------------------------- | --------------------------------------------- | -------------------------------------- |
| 调查/观察 | 访谈、记录客流、看竞品、整理评价   | 揭示一条或多条 Evidence                       | 原则上不直接大幅改指标，只改变证据修正 |
| 测试/打样 | 小样、压力测试、触点测试、携带测试 | Evidence + 可选 readiness 修正                | 可小幅改变准备度或降低不确定性         |
| 准备/谈判 | 询价、签备用供货、排班、写服务边界 | CostRange、RiskMitigation 或 CapacityModifier | 直接改变成本、风险或承接条件           |

#### 一次付费，一次产出

玩家在“执行行动”时支付资源；随后打开行动结果不再扣行动力。`evidence_viewed` 改为非结算阅读事件，或由 `question_action_executed` 同时记录揭示结果。

禁止出现：

- 先花 1 AP 做现场观察，再花 1 AP 查看这次观察的事实；
- 行动完成后只显示“已完成”，没有任何产出；
- 执行询价却只得到品牌指标加分；
- 调查完成后解锁一个此前看不到的正确方案。

#### R01 示例结构

问题一：谁更可能稳定来买？

- 免费事实：上午居民经过较多，下午游客停留更久；
- 行动：记录两个时段各 20 名路人的停留与购买；
- 产出：居民与游客的到店时段、停留时间和购买原因；
- 帮助比较：居民优先、游客优先、双时段试卖；
- 仍未知：复购和可接受价格。

问题二：店里能不能同时服务两类人？

- 免费事实：筹备团队只有两人；
- 行动：盘点产品步骤和两人的高峰工作量；
- 产出：双线运营的额外步骤、预计等待与人手缺口；
- 帮助比较：双时段试卖和游客复杂产品；
- 仍未知：后续是否能招到合适人手。

#### 建设路径

- `V11StageAction` 增加 `questionId`、`outputType`、`revealsEvidenceIds`、`readinessEffects`、`helpsCompareChoiceIds`、`remainingUnknown`。
- `V11Round` 增加 `decisionQuestions[]` 与 `knownFacts[]`。
- 删除学生端独立付费 Evidence 列表，改为问题组中的行动结果卡。
- 保留 Evidence 为规则与报告对象，但由行动揭示。
- 免费已知事实不写入“玩家主动使用证据”的成就判断。

#### 验收

- 每项付费行动至少产生一个玩家可见、可审计的结果；
- 每轮最多 3 个问题组，同组行动回答同一问题但方法和代价不同；
- 同一证据不被重复收费；
- 未行动玩家仍能看到所有基础战略方案；
- 试玩者能说出“我为什么花这点行动力，它帮助我比较了什么”。

### 4.4 战略方案、预选与详情比较

每轮保留 5 个主要方案，以维持开放性和路线深度；不再增加第六个伪装成方案的“跳过”。五个方案必须至少覆盖三种不同经营目标或资源策略。

#### 手机摘要卡

只显示：

- 方案名称；
- 一句具体做法；
- 现金；
- 2—4 点战略行动力；
- 准备天数；
- 工作量等级；
- 当前情报关系的一个摘要图标。

#### 详情卡

详情按以下顺序：

1. 具体做法；
2. 最可能获得的经营收益；
3. 最突出风险；
4. 现金、时间、工作量和组织要求；
5. “你掌握的信息怎么说”；
6. 可选风险预案；
7. 关键轮的一键判断；
8. 执行前总确认。

情报关系必须显示具体对象：

- 哪条行动结果支持这项方案的哪一部分；
- 哪条结果提醒什么风险；
- 哪些重要问题仍未调查；
- 多条证据冲突时，不替玩家下结论。

#### 提交预检

执行按钮旁实时显示：

- 提交后剩余现金；
- 将推进多少天；
- 当前工作量是否超过承接安全区；
- 已选择预案的额外成本；
- 是否满足视觉选择等必要前置条件。

预选不改变状态，不扣资源；正式提交只有一次原子动作。重复点击通过幂等键防止重复扣费。

### 4.5 风险预案与关键轮判断

“执行前判断”不再每轮出现，也不再使用长表单。

#### 风险预案

- 位于方案详情中；
- 是真实经营行动，消耗自由行动力和/或现金；
- 只处理一个明确风险；
- 风险未发生时不退还投入；
- 不能变成所有方案都应购买的必选保险；
- 同轮原则上最多选择一项预案。

#### 关键轮一键判断

只在 R01、R05、R08、R11 出现，玩家用一次点击完成：

> 我认为这次最先改善的是：顾客购买 / 品牌识别 / 交付稳定 / 其他本轮配置项。

它：

- 不消耗行动力；
- 不改变经营结算；
- 不需要输入理由；
- 在结果页即时对照“预期—实际”；
- 命中时提供一个轻量“判断印章”，不加现金或核心分数；
- 最终报告分析玩家长期高估或忽略了什么；
- 教师后台可以聚合全班判断偏差。

这保留教学价值，又不会让每轮节奏被预测问卷打断。

### 4.6 时间与经营经济

时间系统要体现开店规律，而不是只显示累计“第 N 天”。

#### 玩家显示

- 主 HUD 显示“第 2 月 · 产品打样期”等阶段；
- 详情显示某行动或方案需要几天；
- 结果页显示日期推进、是否赶上节点、超期增加了什么成本；
- 账本保留精确天数和金额。

#### 规则

- R01—R05 为开业前，不产生门店经营收入；
- R06 起进入试营业与正式经营，产生基础毛利与固定支出；
- 行动和战略方案均可推进时间，但打开结果、阅读情报和预选方案不推进时间；
- 超过阶段目标日才产生延期固定成本；
- 不同战略方案的准备时间必须在现实上可比较；
- 价格、成本和收入继续使用经过课程负责人审校的人民币基准。

#### 结果可解释性

每笔现金变化必须标记来源：

- 调查/测试；
- 战略投入；
- 风险准备；
- 固定经营成本；
- 经营毛利；
- 事件收入或损失；
- 延期成本。

玩家层不展示完整会计系统，但可以展开“本轮钱花到哪里”。

### 4.7 经营看板与指标可读性

指标继续分成两组：

#### 顾客怎么回应

- 知名度；
- 购买转化；
- 信任；
- 复购；
- 人群匹配。

#### 店铺能不能接住

- 交付能力；
- 组织承接力；
- 品牌一致性；
- 视觉识别；
- 视觉适配；
- 文化可信度；
- 渠道依赖；
- 声誉负债。

#### 推荐呈现方案

普通指标使用“五段状态条”：

|   数值 | 状态     | 解释                       |
| -----: | -------- | -------------------------- |
|   0—19 | 已经失控 | 当前问题正在直接伤害经营   |
|  20—39 | 明显吃紧 | 再增加负担很可能出问题     |
|  40—59 | 勉强够用 | 能维持现状，不适合贸然扩张 |
|  60—79 | 基本稳住 | 可承接适度增长，仍需留缓冲 |
| 80—100 | 很稳     | 当前条件下有较强余量       |

交付能力和组织承接力额外使用“能力—压力双条”：

```text
当前能力  62  ████████████░░░░░░
当前压力  57  ███████████░░░░░░░
安全余量  +5  基本够用；不适合突然翻倍接单
```

这样比单独显示“62”更直接，也能解释同一个能力值为什么在不同客流下含义不同。

每项指标还显示：

- 当前状态标签；
- 相比上轮的趋势；
- 最近一次主要变化来源；
- 点按后的简短解释；
- 对顾客还是对店铺产生意义。

禁止公开隐藏精确公式和所有内部因子，避免玩家把游戏变成算分表。

### 4.8 结果页、世界变化与延迟后果

每轮结果必须独立成页，不得只在原卡片下追加一串数字。

顺序固定为：

1. 结果图或 1.5—3 秒短动效；
2. 角色的一句即时反应；
3. 顾客发生了什么；
4. 店铺发生了什么；
5. 现金、时间、工作量和指标变化；
6. 本轮触发的事件；
7. 已埋下但尚未发生的风险；
8. 可展开的因果解释；
9. 进入下一轮。

#### 三类反馈同时存在

- 数值反馈：现金、时间、指标和能力—压力变化；
- 叙事反馈：人物反应、顾客行为、供应商或合作方变化；
- 视觉反馈：店招、包装、排队、设备、角色表情和店铺状态发生改变。

#### 延迟后果

结果页只提示“以后可能回来找你的问题”，不直接泄露精确到期轮次。到期时必须显示原始来源：

> 第 3 轮选择复杂招牌产品后，高峰制作步骤增加；这项压力在本轮订单增长时兑现。

#### 突发事件

- 可以奇葩、荒诞、带梗，但必须发生在现实经营逻辑内；
- 事件由前置选择、指标或固定种子决定；
- 不能用纯随机大事件把玩家前面的努力全部抹掉；
- 事件至少提供一个可理解的结果，不只承担笑点。

### 4.9 品牌名与视觉经营子系统

视觉玩法分成三个阶段，避免所有课程知识挤在 R08 一轮。

#### R05：命名与身份架构

玩家完成：

- 自填品牌名；
- 声明命名意图；
- 选择品牌人格方向；
- 决定视觉资产架构：文字标志优先、符号优先、IP 辅助或克制 VI。

系统不评价名称语义质量，只检查：

- 格式与禁用词；
- 是否完成命名；
- 玩家声明的意图；
- 后续是否持续应用在触点中。

#### R08：视觉系统比较

6 套视觉系统全部可以查看，玩家最多把 3 套加入对比栏。每套至少提供统一模板下的：

- 店招；
- 杯体或杯套；
- 外带包装；
- 手机头像或社交页面；
- 单色版本；
- 小尺寸或遮挡状态。

文字标志系统、符号系统和 IP 角色系统必须在图形结构上明显不同，不能只换颜色。

玩家自填品牌名通过 SVG/Canvas 模板实时合成到店招、杯体和头像中。合成只做排版和长度适配，不做 AI 评分。

#### R09：包装与传播使用

玩家检验：

- 包装在携带、沾水、折叠和遮挡时是否仍可识别；
- IP 是否有明确使用任务；
- 包装是否增加制作、库存和服务负担；
- 顾客带离老街后，视觉是否仍然属于这家店。

#### 视觉结算

视觉结果由以下因素确定性计算：

```text
视觉方案基础能力
× 目标顾客匹配
× 品牌定位匹配
× 产品与价格匹配
× 文化路线匹配
× 触点要求
- 制作成本
- 维护工作量
```

不存在全路线最优方案；IP 路线和无 IP 路线都必须可达到高等级。

#### 正式资产门禁

- 关键视觉提案不能依赖通用占位图进入课程发布；
- 每套正式方案必须有四个以上触点图；
- 结果页和章节卡至少有路线可见差异；
- 单个非关键插图缺失可以回退，LOGO/IP/包装比较图缺失必须阻止发布。

### 4.10 进度、成就与过程激励

激励服务于“我学会了经营判断”，不能奖励机械点完所有按钮。

#### 年度进度

常驻提供简化的十二轮年度路线图，只显示：

- 当前月份和章节；
- 已完成回合；
- 当前经营阶段；
- 下一次章节体检。

#### 章节体检

R02、R06、R09、R12 后显示图文卡：

- 当前最强的一项；
- 当前最大矛盾；
- 顾客和店铺各一张状态图；
- 一项未来风险；
- 下一章会面对的问题。

章节体检不额外评分，不要求玩家填写答案，阅读后即可继续。

#### 成就

首版目标为 10—14 个过程成就，分为：

- 证据使用：查看并真正采用相关信息；
- 风险管理：预案在真实风险中生效；
- 视觉判断：完成两类以上触点测试后选择系统；
- 一致性：跨轮保持顾客、产品、视觉和服务协调；
- 修复能力：后续行动修复自己早期造成的矛盾；
- 克制经营：在增长机会前主动控制规模；
- 路线探索：形成不同但可持续的品牌路线。

成就不能：

- 仅因进入下一轮自动获得；
- 鼓励把所有行动和情报全部点完；
- 增加现金或核心经营分数；
- 暗示唯一正确路线。

#### 即时奖励

成就、关键判断命中和章节完成使用短动画、徽章、角色反应或店铺变化反馈。减少动效模式仍显示完整文字和图形状态。

### 4.11 胜利、经营等级、路线称号与班级比较

#### 个人胜利

一年结束后分别计算：

- 经营生存 25%；
- 顾客资产 25%；
- 品牌资产 30%；
- 系统一致性 20%。

基础胜利条件：店铺未发生严重破产或交付崩溃，综合评价达到“形成品牌”及以上。

经营等级回答“做得怎么样”，路线称号回答“做成了什么样的品牌”。二者必须分开：

- 经营失控；
- 勉强活着；
- 形成品牌；
- 鲜明且可持续；
- 年度标杆。

路线称号至少覆盖：

- 社区关系型；
- 游客传播型；
- 文化精品型；
- 高效率大众型；
- 视觉驱动型；
- 平台增长型；
- 小众忠诚型。

#### 班级比较

不采用公开实名的“利润总榜”。系统生成匿名多类别结果：

- 最赚钱品牌；
- 最受顾客信任；
- 最强品牌资产；
- 最稳经营；
- 最会使用证据；
- 最有效风险预案；
- 综合经营最佳。

学生个人页可以看到自己的经营等级、路线和班级匿名区间；教师可选择匿名案例进入课堂讨论。讨论加分由教师在课程评价中另行处理，不写回游戏结算。

### 4.12 手机端信息架构

默认竖屏，不要求学生横屏。

#### 页面状态栈

```text
join
→ onboarding
→ chapterIntro
→ roundBrief
→ questionBoard
→ actionOutcomeSheet
→ choiceList
→ choiceDetail
→ visualCompare / keyPrediction
→ roundResult
→ eventResult
→ chapterReview
→ finalReport
```

栈顶页面独占输入。打开底部卡、术语卡或视觉比较时，背景不可继续点击；关闭后恢复原焦点和滚动位置。

#### 页面信息分层

长期显示：

- 当前月份/章节；
- 现金；
- 自由行动力；
- 战略行动力；
- 当前任务；
- 主要继续按钮。

底部卡或抽屉显示：

- 方案详情；
- 情报全文；
- 指标解释；
- 术语解释；
- 账本明细；
- 历史变化来源。

全屏显示：

- 序章；
- 章节开场；
- 视觉提案比较；
- 重大突发事件；
- 回合结果；
- 章节体检；
- 年度结局。

#### 响应式要求

- 主参考视口 390×844，最低宽度 320；
- 关键触控目标不小于约 44×44 CSS 像素；
- 顶部和底部固定区域使用安全区 inset；
- 视觉提案允许横向滑动，普通经营流程不出现横向页面滚动；
- 900 像素以上桌面使用列表—详情双栏；
- 选中、风险、支持和禁用状态不能只依靠颜色；
- 提供文字大小和减少动效；
- HUD 由状态变化事件更新，不通过定时轮询刷新。

### 4.13 教师后台与决策过程数据

教师必须能够查看学生“怎样走到结果”，不只看最终分数。

#### 单生时间线

每轮显示：

- 免费事实已读状态；
- 执行了哪些调查、测试、询价或准备；
- 每项行动花费的自由行动力、现金和时间；
- 揭示了哪些 Evidence；
- 预览过哪些战略方案及比较次数；
- 最终选择或主动跳过；
- 是否配置风险预案；
- 关键轮预期与实际；
- 即时、延迟和到期后果；
- 视觉选择、触点测试和品牌名声明；
- 成就、章节体检和最终路线。

#### 班级聚合

- 自由行动力分配；
- 各问题组被调查比例；
- 信息查看后方案选择变化；
- 跳过率；
- 方案、路线和经营等级分布；
- 风险预案使用和命中；
- 关键判断偏差；
- 视觉系统和身份架构选择；
- 典型一致、矛盾、修复和失败路径。

#### 内容不可变性

班级创建时绑定：

- `contentVersion`；
- `engineVersion`；
- `reportVersion`；
- 内容校验和；
- 班级种子。

发布后教师只能：

- 开放或关闭加入；
- 查看和导出数据；
- 选择匿名课堂案例；
- 归档班级；
- 按明确数据生命周期删除整班数据。

教师不能编辑内容、成本、权重、事件、成就、结局、学生状态和最终报告。需要修改内容时，只能发布新版本并创建绑定新版本的新班级。

#### 建议状态

```text

├─ keyPredictions[]
```

#### 动作协议

| 动作                          | 是否结算 | 说明                              |
| ----------------------------- | -------- | --------------------------------- |
| `onboarding_completed`        | 否       | 完成序章                          |
| `question_action_executed`    | 是       | 支付资源并揭示证据或改变准备条件  |

| `visual_tested`               | 是       | 支付自由行动力并产生触点诊断      |
| `choice_committed`            | 是       | 使用战略行动力原子执行方案        |
| `choice_skipped`              | 是       | 允许回合直接结算维持现状          |
| `round_result_acknowledged`   | 否       | 记录结果已读，不影响结算          |
| `chapter_review_acknowledged` | 否       | 记录章节体检已读                  |

#### Trace

每次正式结算至少记录：

- 结算前后双层行动力、现金、时间和指标；
- 行动产出与揭示证据；
- 情报对方案的支持、提醒、冲突和有限修正；
- 风险预案投入、是否触发和减损；
- 关键判断与实际对照；
- 即时效果；
- 新排入的延迟效果；
- 本轮到期的历史效果及原始来源；
- 跳过的自然后果；
- 财务明细；
- 事件、成就、人物和画面键；
- 理论映射。

客户端只提交动作 ID、选择 ID 和玩家输入值，不提交成本、指标变化、匹配分、结局或报告结论。

## 5. 平衡原则与防支配策略

### 5.1 有意义的稀缺

- 玩家不能完成本轮全部行动；
- 自由行动力应允许典型组合为“2+2”“2+1+1”或“1+1+1+1”；
- 调查全部内容不能成为唯一最优策略；
- 风险预案不能每轮必买；
- 时间和现金要产生不同取舍，不能只换算成同一种分数。

### 5.2 方案平衡

- 每项方案至少在一种可达路径中有优势；
- 每项方案至少有一种明确局限；
- 不允许一个方案在现金、时间、工作量、顾客和品牌指标上全面占优；
- 证据修正原则上只占单项结果的 10%—20%；
- 调查可以提高判断质量，但不能把某个方案变成必胜答案；
- 视觉方案在不同客群、价格、产品和触点路线中表现不同。

### 5.3 跳过率与失败率目标

试玩阶段建议观察，而不是硬编码：

- 允许跳过回合的跳过率目标区间 5%—30%；
- 若长期低于 5%，说明跳过没有真实意义或入口不可见；
- 若高于 30%，说明该轮方案吸引力不足、成本过高或玩家疲劳；
- 经营失控、勉强活着、形成品牌和高等级结果都应可达；
- 任一成功路线不得超过全部成功路径的 45%。

## 6. 分阶段建设计划

本升级建议作为 M16—M22 执行。必须按顺序推进；每阶段先补测试并通过，再进入下一阶段。

### M16：状态协议与防死局

建设：

- 新增 v1.2 内容、引擎、动作和报告版本；
- 建立双层行动力；
- 增加 `skipPolicy` 与 `choice_skipped`；
- 建立现金和行动力的回合出口预检；
- 保持 v1.1 历史回放不变。

测试：

- 双层行动力单元测试；
- 必选轮与可跳过轮矩阵；
- 现金最低路径和自由行动力归零路径；
- 10,000 局无死局性质测试；
- v1.1 黄金日志哈希不变。

退出条件：任意合法状态都能结束当前回合，且不会借用被保留的战略行动力。

### M17：问题板与行动—证据合并

建设：

- 增加 `decisionQuestions`、`knownFacts` 和结构化行动产出；
- 12 轮按问题重组行动；
- 行动执行时揭示 Evidence，阅读结果不再扣资源；
- 详情卡显示信息如何支持、提醒或冲突。

测试：

- 每项行动均有产出；
- 同一证据只收费一次；
- 所有方案始终可见；
- Evidence 引用与报告回指完整；
- R01、R05、R08、R11 端到端流程。

退出条件：试玩者能解释每次行动具体帮助了哪项判断。

### M18：战略比较、预案和关键判断

建设：

- 统一战略行动成本；
- 重做摘要、详情、预检与原子提交；
- 风险预案使用自由行动力；
- 关键四轮加入一键判断与结果对照；
- 跳过确认和结果页完成。

测试：

- 预选不扣资源；
- 重复提交不重复扣费；
- 预案生效、未触发和浪费；
- 关键判断不影响结算；
- 跳过与普通选择的报告区分。

退出条件：单轮没有额外表单拖慢，且风险与判断仍有教学记录。

### M19：看板、时间与手机主流程

建设：

- 顾客/店铺指标分组；
- 五段状态条与能力—压力双条；
- 时间显示改为月份、阶段和节点；
- 问题板、详情卡和结果页进入状态栈；
- 安全区、焦点恢复、文字大小和减少动效完善。

测试：

- 指标区间边界；
- 交付能力与压力组合；
- 320、360、390、430、768、1366 宽度；
- iOS/Android 安全区和返回行为；
- 键盘、触摸和屏幕阅读顺序。

退出条件：普通回合不再像连续长问卷，手机任一主任务控制在约 1.2 个视口内。

### M20：品牌名与正式视觉经营

建设：

- R05 品牌名、命名意图、人格和身份架构；
- 本地确定性格式校验；
- 6 套视觉系统的正式 LOGO、IP、包装与四触点图；
- SVG/Canvas 将学生品牌名合成到触点；
- R08 三套对比栏和触点测试；
- R09 包装使用测试；
- 关键视觉资产发布门禁。

测试：

- 中英文名称长度和安全输入；
- 不调用外部 API；
- 视觉资产引用完整；
- 三类视觉系统图形结构不同；
- 同一视觉在不同路线中诊断不同；
- 手机放大、横滑和对比栏。

退出条件：学生能从图中指出方案差异，并看见自己填写的名称进入真实触点。

### M21：结果世界、章节体检与激励

建设：

- 为每轮主要结果制作场景图、角色反应和轻量动效；
- 完成延迟后果来源反馈；
- 增加四次章节体检；
- 建立 10—14 个过程成就；
- 扩展路线称号和结局画面；
- 完成匿名分类奖项。

测试：

- 每轮至少一项数值、一项叙事和一项视觉反馈；
- 延迟效果能回指原始选择；
- 成就不能靠正常推进全部获得；
- 失败路径仍能完成报告；
- 减少动效时信息完整。

退出条件：十二轮能呈现阶段变化，不再只是重复选择和数字加减。

### M22：教师分析、平衡与正式发布

建设：

- 教师时间线增加双层行动力、问题组、跳过、关键判断和品牌视觉数据；
- 班级聚合增加行动分配、跳过率、判断偏差和视觉路线；
- 更新学生报告和匿名案例；
- 50,000 局模拟、真人试玩、真机和 80 人发布演练；
- 冻结 v1.2 内容包和校验和。

测试与人工门禁：

- `pnpm lint`；
- `pnpm typecheck`；
- `pnpm test`；
- v1.1 与 v1.2 发布检查；
- 3—5 人无指导首轮测试；
- 8—12 人完整平衡试玩；
- 真实 iPhone、Android Chrome 和微信内置浏览器；
- 生产环境 80 人加入、提交、刷新恢复和报告；
- 课程负责人对流程、视觉、价格和教学因果签字。

退出条件：自动化、真人理解、真机和课程内容四类门禁全部通过。

## 7. 关键自动化测试清单

### 7.1 引擎

- 自由行动力不能动用战略行动力；
- 战略行动力不能用于调查或预案；
- 自由行动力归零后仍可提交战略方案；
- 指定五轮可跳过，其余七轮拒绝跳过；
- 跳过结算固定成本、收入和到期效果；
- 行动执行与 Evidence 揭示原子完成；
- Evidence 阅读不重复扣费；
- 现金、时间和账本来源一致；
- 关键判断不改变指标；
- 所有结果确定性可重放；
- 旧版本历史不被新默认值解释。

### 7.2 内容

- 每轮 2—3 个问题组；
- 每项付费行动有具体产出；
- 每项行动关联至少一个问题；
- 每条 Evidence 有来源行动或明确免费来源；
- 每轮 5 个方案至少覆盖 3 种经营目标；
- 必选轮存在最低现金可达方案；
- 视觉关键轮有真实资产；
- IP 路线与无 IP 路线均可达到高等级；
- 成就条件不是单纯回合完成；
- 章节体检引用的数据可解析。

### 7.3 学生端 E2E

- 序章说明角色、资源和综合胜利；
- 4 点自由 AP 花完后仍能使用本轮剩余的 4 点战略 AP；
- AP 即将归零确认；
- 行动结果揭示证据并更新方案关系；
- 选择预览、切换和正式提交；
- 指定回合主动跳过；
- 视觉名称合成和触点测试；
- 结果图、人物、指标和延迟提示；
- 章节体检和年度结局；
- 刷新、断网、重复点击和恢复；
- 手机安全区、底部卡焦点和返回键。

### 7.4 教师端与隐私

- 教师可查看逐项决策过程；
- 教师不能调用任何内容修改或重新结算接口；
- 匿名案例不包含姓名、学号、会话标识和内部 ID；
- 发布后内容版本和校验和不可变；
- CSV 能区分首局、重玩、选择和主动跳过；
- 删除整班数据需要明确权限和审计记录。

## 8. 真人试玩验收问题

不向玩家解释规则答案，试玩后让学生回答：

1. 这局怎样才算赢？
2. 自由行动力和战略行动力分别做什么？
3. 你为什么花行动力做某项行动？它具体帮你比较了什么？
4. 哪条信息支持了你的选择，哪条信息只是提醒风险？
5. 你有没有主动跳过一轮？为什么？
6. 哪个选择的后果不是立刻发生的？
7. 为什么同一套视觉不一定适合所有品牌路线？
8. 你的品牌名、LOGO、IP 或包装分别承担了什么任务？
9. 哪次选择让顾客指标变好，却让店铺更吃力？
10. 你会把哪项游戏经验带进课程作业？

验收目标：

- 80% 以上玩家能说明综合胜利目标；
- 100% 玩家不会因行动力用尽而卡死；
- 80% 以上玩家能解释一次行动—证据—选择关系；
- 80% 以上玩家能说出顾客指标与店铺指标的区别；
- 90% 以上玩家能从图中识别文字标志、符号和 IP 路线的区别；
- 大多数玩家能指出至少一条跨轮因果；
- 中位首局时长 35—50 分钟；
- 没有单一方案被普遍认为是教师设置的标准答案。

## 9. 完成定义

只有同时满足以下条件，本轮流程与机制升级才算完成：

- 双层行动力上线，所有合法路径无推进死局；
- 指定回合的主动跳过完整进入引擎、UI、报告和教师分析；
- 行动与情报按问题组重构，一次付费产生一次明确产出；
- 所有战略方案始终可见，情报不解锁隐藏正确答案；
- 看板能用状态条和能力—压力关系解释指标是否够用；
- 品牌名进入状态和视觉触点，且不调用 AI/API 评价；
- LOGO、VI、IP、包装存在真实且明显不同的示意图；
- 每轮结果同时具有数值、叙事和视觉反馈；
- 四次章节体检、过程成就和多路线结局完整；
- 手机端流程不再呈现为一张连续长问卷；
- 教师能查看完整决策过程，但不能修改发布内容或学生结果；
- 学生报告能解释选择、证据、资源、即时后果、延迟后果和理论；
- 自动化测试、真人试玩、真实设备、80 人发布演练和课程负责人终审全部通过；
- v1.1 历史首局、报告和内容校验继续可读取，不被 v1.2 覆盖。

本文与《游戏文本全面升级指导 v1.2》共同构成下一阶段的建设依据：本文决定流程和规则如何工作，文本指导决定玩家看到的话如何表达。任何一方单独完成，都不能视为游戏体验升级完成。
