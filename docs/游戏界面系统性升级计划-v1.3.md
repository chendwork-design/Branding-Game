# 老街品牌局：游戏界面系统性升级计划 v1.3

> 适用范围：学生端 `/v11`，兼顾手机、平板、电脑与课堂投影。
>
> 本文只调整界面结构、操作流程、视觉反馈和资源规范，不修改服务端结算、内容版本、首局/重玩隔离及教师数据规则。

## 1. 结论

当前界面已经具备基础响应式能力、抽屉、对话框、指标进度条与安全区处理，但它仍然更像“会随屏幕变窄的长表单”，还没有形成手机与电脑各自合适的游戏操作台。

本轮升级采用以下总原则：

1. 同一份游戏状态，按设备重排成两种任务界面；不把桌面页面简单压成手机长页。
2. 手机端一次只处理一个任务；电脑端同时展示“现场—决策—依据”，但只突出一个主操作。
3. HUD只显示当前决策必需的信息，完整指标进入经营看板。
4. 事实、选择、后果在界面上形成可追踪的连接，减少玩家依赖短时记忆。
5. 功能图标使用统一SVG系统；ImageGen主要承担场景、结果和章节奖励画面，不承担需要精确识别的UI图标、LOGO文字和数值图表。
6. 图片必须反映本局经营状态，而不是只做装饰；玩家的选择应能改变结果画面中的顾客、店员、门店、包装或视觉路线。

## 2. 当前界面实测与主要问题

### 2.1 实测结果

本次检查了当前 `/v11` 的回合说明页和经营现场页。

| 场景         |       视口 | 页面高度 | 观察                                                        |
| ------------ | ---------: | -------: | ----------------------------------------------------------- |
| 手机回合说明 |  390 × 844 |  1566 px | 约1.85屏；HUD、四项资源和12回合进度占据首屏大部分空间       |
| 手机经营现场 |  390 × 844 |  2862 px | 约3.39屏；行动、证据、视觉入口、战略选择连续纵向堆叠        |
| 电脑经营现场 | 1366 × 768 |  2246 px | 约2.92屏；内容仍是约1048 px的单列，横向空间未转化为决策效率 |

手机端部分概念按钮和辅助按钮高度约34—40 px，低于本计划统一采用的44 px最低触控高度；年度12回合节点被压进一条很细的横线；本轮插图在说明文字之前出现，反而推迟了玩家看到“这一轮要做什么”。

### 2.2 结构问题

| 问题                     | 玩家感受                                 | 根因                               | 修改方向                                |
| ------------------------ | ---------------------------------------- | ---------------------------------- | --------------------------------------- |
| HUD过高且每屏重复        | 刚进入页面，先看到大量状态而不是任务     | 四项资源、标题和12回合进度同时常驻 | 收成紧凑HUD；完整信息进入看板           |
| 经营现场是一条长链       | 像在填写问卷，玩家不知道自己当前在哪一步 | 行动、证据、选择按文档顺序堆叠     | 改成任务状态栈和阶段导航                |
| 行动结果与战略方案离得远 | 看完事实后还要记住它，再下滑寻找方案     | 事实独立成整块，未绑定到方案       | 把“支持/警告”直接挂到方案比较中         |
| 桌面端仍是单列           | 空间大但效率没有提升                     | 只有一个最大宽度容器，没有任务分区 | 改成三栏经营工作台                      |
| 资源数字缺少动作语义     | 知道还剩多少，不知道这意味着还能做什么   | 资源卡只显示数值                   | 增加“还能调查2次/还能提交1项方案”等解释 |
| 选项信息权重相同         | 标题、成本、风险、描述都在抢注意力       | 卡片缺少摘要与详情层级             | 默认显示差异，详情用抽屉/侧栏展开       |
| 英文字母选项图标弱       | N/T/H等既不直观，也不利于课程概念记忆    | 用字母代替语义图形                 | 改为路线图标和颜色/形状双编码           |
| 图像反馈与状态连接不足   | 图片好看也不一定让人觉得“这是我的结果”   | 结果图主要按回合分类               | 按路线、结果强度和风险状态组合画面      |

## 3. 目标体验与信息优先级

每一轮玩家只需要清楚回答五个问题：

1. 店里现在发生了什么？
2. 这一轮必须决定什么？
3. 我还可以花多少资源去弄清情况？
4. 哪些事实支持或警告某个方案？
5. 我选完后，顾客、店铺和品牌发生了什么？

界面优先级固定为：

```text
当前任务 > 可执行操作 > 与操作直接相关的资源 > 方案差异 > 完整解释 > 全局数据
```

完整理论、所有指标、全年轨迹和教学解释仍然保留，但通过看板、术语浮层、结果解释与最终报告按需展开。

## 4. 跨设备布局规范

### 4.1 统一断点

| 模式    | 宽度        | 主要用途        | 页面组织                           |
| ------- | ----------- | --------------- | ---------------------------------- |
| Compact | 320—479 px  | 学生手机        | 单任务状态栈 + 底部操作条          |
| Medium  | 480—899 px  | 大屏手机/平板   | 单列或主次双列，详情为侧滑抽屉     |
| Wide    | 900—1439 px | 笔记本/普通电脑 | 三栏经营工作台                     |
| Large   | ≥1440 px    | 大屏电脑/投影   | 三栏保持上限，外围留白承载场景背景 |

CSS不以具体机型为核心，而以“内容是否还能保持可读与可操作”为断点依据。全局必须继续使用 `env(safe-area-inset-*)`，浮层和底栏不得覆盖刘海、圆角和系统手势区域。

### 4.2 手机端：单任务状态栈

```text
┌──────────────────────────┐
│ 1/12  本轮目标       看板 │  56—64 px，吸顶
│ ¥50万  自由4  战略2       │  资源压缩成一行
├──────────────────────────┤
│ 当前步骤：先弄清情况  1/3 │
│ ███████░░                │
├──────────────────────────┤
│                          │
│ 当前任务卡 / 场景 / 方案 │  一次只呈现一个主任务
│                          │
│ [展开依据] [查看详情]     │
├──────────────────────────┤
│ 上一步        继续比较 → │  64—72 px，底部安全区
└──────────────────────────┘
```

手机端规则：

- 页面左右内边距16 px；320—359 px时允许降到12 px，不低于8 px。
- 所有主要触控目标最小48 × 48 px，次要目标最低44 × 44 px；相邻触控目标至少8 px间隔。
- 每个阶段只有一个主按钮。固定底栏显示当前阶段最重要的动作，例如“去看方案”“提交这条路线”“确认结果”。
- 玩家进入经营现场后，第一项可执行操作应在首屏内出现；不要求玩家先滑过完整HUD和说明。
- 主任务内容目标控制在1.2个视口内。长解释折叠到“为什么/这意味着什么”。
- 手机返回键、浏览器返回和界面返回统一遵循状态栈：详情 → 比较 → 行动 → 回合说明；不得直接退出本局。

### 4.3 电脑端：三栏经营工作台

```text
┌──────────────┬────────────────────────┬─────────────────┐
│ 现场与资源   │ 当前任务               │ 决策档案        │
│ 260—288 px   │ 600—720 px             │ 300—336 px      │
│              │                        │                 │
│ 本轮目标     │ 行动卡 / 方案比较      │ 所选方案详情    │
│ 关键事实     │ 结果页主画面           │ 成本、依据、风险│
│ 简化全年进度 │                        │ 提交按钮        │
└──────────────┴────────────────────────┴─────────────────┘
```

电脑端规则：

- 主容器宽度上限1360 px，推荐使用12列网格；900—1119 px可退化为“主区 + 右侧详情”双栏。
- 左栏和右栏在内容允许时保持粘性；中栏独立增长。不能让整个页面因为一张详情卡增长到三屏。
- 左栏放现场和当前资源，右栏放当前选中方案；不要在三个区域重复同一段文字。
- 选项列表一次显示3—5个精简方案；点击后在右栏更新详情，不打开覆盖全屏的对话框。
- 键盘用户可用Tab移动焦点，用方向键切换同组方案，Enter打开/选择，Esc关闭详情或返回上一级。

### 4.4 平板与课堂投影

- 平板横屏使用双栏：左侧任务约58%，右侧方案详情约42%。
- 平板竖屏沿用手机状态栈，但允许证据和选项各显示两列。
- 增加匿名“课堂投影模式”：隐藏姓名、学号和个人记录，只显示回合、路线分布、匿名结果与讨论问题；字号整体放大至1.25倍。

## 5. 页面流程重组

一轮固定为六个屏幕状态：

```text
回合简报 → 调查行动 → 事实整理 → 方案比较 → 承诺确认 → 经营结果
                   ↘ 视觉比较（仅指定回合） ↗
```

### 5.1 回合简报

首屏只保留：场景标题、一句现场变化、本轮必须完成的目标、一张场景图和“进入现场”。“为什么现在”“两难”和术语解释放在可展开层；首次出现的关键术语仍主动提示，但不自动遮挡主任务。

手机端先显示文字目标，再显示160—200 px高的场景图；电脑端图文并列。12回合全年进度改为“第1/12回合 + 当前章节 + 细进度条”，点击后再展开全年时间线。

### 5.2 调查行动

行动按“要回答的问题”聚类，每组先显示问题，再显示最多2—3个行动。行动卡默认只展示：

- 行动名称；
- 会弄清什么；
- 现金/自由行动/天数；
- 当前是否可执行。

“做完仍不知道什么”进入详情，不与主操作争夺空间。完成行动后，卡片原位转化为结果摘要，并提供“带着这条事实去比较方案”。

### 5.3 事实整理

不再把所有证据作为一整段独立长列表。采用“事实收件箱”：

- 新得到的事实以小票/便签形式即时出现；
- 每条事实标记“更支持”“提醒风险”或“补充情况”；
- 点击关系标签直接跳到对应方案；
- 未取得的事实只显示数量和取得方式，不展示一排禁用卡片。

### 5.4 方案比较

默认方案卡只显示四项：路线名称、一句话代价、一句话主要收益、相关事实数量。选择一个方案后再展示现金、行动力、天数、工作量、即时收益、延迟风险、已有情报是否支持。

手机端最多把2个方案加入“对比盘”，在底部抽屉中逐项比较；电脑端右栏固定显示当前方案，可将另一个方案钉住对比。不能要求玩家同时记住5张长卡。

事实关系采用三种形状与文字双编码：

- 绿色圆形勾：已有事实支持；
- 琥珀三角：已有事实提醒风险；
- 灰色空心圆：仍缺少信息。

### 5.5 承诺确认

确认页只回答“选什么、花什么、赌什么”。不重复所有背景。

必须显示：提交后剩余现金、战略行动消耗、推进天数、工作量压力、最主要风险和是否做过对应预案。主按钮使用具体动词，例如“投入3万元，执行居民日常路线”。

### 5.6 经营结果

结果页顺序固定为：

1. 结果画面与一句现场反应；
2. 现金、时间、工作量的即时变化；
3. 顾客与店铺分别发生的变化；
4. 解锁成就或过程反馈；
5. “为什么会这样”和课程理论；
6. 进入下一轮。

手机端第一屏应同时看见结果图、现场反应和至少一项关键变化。理论解释默认折叠，但若玩家判断命中、延迟效果兑现或发生重大反转，应在结果中主动出现一条短解释。

## 6. HUD、指标和空间规范

### 6.1 紧凑HUD

手机常驻HUD仅显示：回合、现金、自由行动、战略行动、看板入口。时间合并到回合标题；详细解释放入看板。

电脑端HUD进入左栏，不再横跨整页。资源的主值和动作语义同时显示，例如：

- `自由行动 2` / “还可调查2次”；
- `战略行动 2` / “可提交1项方案”；
- `现金 47万` / “本轮已投入3万”。

当数值变化时，HUD通过事件更新并短暂高亮300—500 ms；禁止轮询。动画只能使用透明度和位移，开启“减少动效”时改为静态描边变化。

### 6.2 指标显示

指标分成两组，不在主HUD常驻：

- 顾客：认知、转化、信任、复购、客群匹配、视觉识别；
- 店铺：产品交付、组织能力、品牌一致性、承诺可信度、文化可信度、声誉负债。

看板使用“数值 + 状态词 + 进度条 + 最近来源”。颜色之外必须有状态词和图形位置。对于交付能力，额外提供“承接能力—当前压力—安全余量”三条关系，让玩家看出“是否够用”，而不是只看到一个孤立分数。

### 6.3 字体与文字

- 手机正文最低15 px，推荐16 px；辅助文字不低于12 px。
- 主要按钮不超过12个汉字；解释性副文案单段不超过60字。
- 标题不使用全大写英文；LOGO、VI、IP等课程约定词可保留。
- 大字号模式下允许容器增长，不得固定高度截字。

## 7. 图标系统

### 7.1 制作原则

功能图标应使用手工绘制SVG，不直接使用ImageGen成品。统一为24 × 24 px视窗、2 px圆角描边、端点圆润，风格取自“老街账本、茶铺工具、木印与铜牌”，避免通用后台图标感。

首次出现时使用“图标 + 中文标签”，熟悉后可在紧凑HUD中只显示图标和数字，但必须保留可访问名称与长按/悬停提示。

### 7.2 必做图标清单

| 类别     | 图标意象                | 用途             |
| -------- | ----------------------- | ---------------- |
| 现金     | 打开的木钱匣 + 一枚铜钱 | 资源、成本、流水 |
| 自由行动 | 放大镜叠脚印            | 调查、测试、询价 |
| 战略行动 | 棋盘上的落子/印章       | 提交战略方案     |
| 时间     | 撕页日历 + 茶叶刻度     | 天数与经营阶段   |
| 看板     | 账簿 + 三条刻度         | 打开完整指标     |
| 已知现场 | 门店招牌 + 感叹点       | 不需花资源的事实 |
| 调研     | 对话气泡 + 放大镜       | 访谈/观察        |
| 测试     | 两只茶杯 + 对勾         | 产品/视觉测试    |
| 询价     | 算盘 + 标签             | 成本边界         |
| 支持     | 圆形勾                  | 证据支持方案     |
| 警告     | 三角感叹号              | 风险证据         |
| 未知     | 空心圆 + 问号           | 仍缺信息         |
| 工作量   | 托盘上堆叠茶杯          | 团队压力         |
| 风险预案 | 雨棚/伞罩住茶杯         | 已配置预案       |

| IP角色   | 人偶头 + 对话气泡       | IP触点与互动     |
| 跳过本轮 | 空棋格 + 右箭头         | 维持现状并结算   |
| 成就     | 铜质店章                | 解锁过程成就     |
| 理论解释 | 书签 + 灯泡             | 展开课程依据     |

### 7.3 成就图标

成就不是纯文字Toast，应形成可收藏的“老街店章”。建议三层规格：HUD新解锁24 px、结果页64 px、成就册96 px。锁定状态显示清晰轮廓和未知条件提示，不能只降低透明度。

首批成就图标建议：

| 成就           | 图形                         | 解锁反馈                 |
| -------------- | ---------------------------- | ------------------------ |
| 先问再押       | 放大镜压在棋子上             | 使用相关事实后提交方案   |
| 钱花在刀刃上   | 铜钱穿过靶心                 | 低浪费完成关键验证       |
| 店里接得住     | 托盘稳稳托住三杯             | 压力未超过承接能力       |
| 说到做到       | 招牌与出杯单对齐             | 承诺可信度和交付同时提升 |
| 一眼认出       | 被遮挡仍完整的符号           | 视觉路线通过关键触点测试 |
| 不只是一张LOGO | 招牌、杯身、头像围绕核心标记 | 视觉系统跨触点稳定       |
| 老街不是背景板 | 砖墙纹样与真实生活场景相扣   | 文化可信度达到阈值       |
| 高峰期没翻车   | 茶杯越过红色压力线           | 高压力事件中保持交付     |
| 留住回头客     | 两位顾客再次进店             | 复购和信任连续增长       |
| 敢于止损       | 剪断亏损流水                 | 识别风险后选择收缩或跳过 |

## 8. 图片、动效与激励反馈

### 8.1 哪些地方必须有图

| 位置           | 是否必须   | 作用                       | 生产方式                                           |
| -------------- | ---------- | -------------------------- | -------------------------------------------------- |
| 序章/章节封面  | 必须       | 建立世界观与章节期待       | ImageGen场景插画                                   |
| 每轮简报       | 必须       | 把抽象经营问题变成现场     | 4张章节底图 + 12组可替换前景，或12张独立图         |
| LOGO/VI/IP比较 | 必须       | 课程核心操作，必须可见差异 | SVG品牌系统 + CSS/HTML触点样机；场景背景可ImageGen |
| 每轮结果       | 必须       | 形成即时反馈与因果感       | ImageGen结果场景 + 状态叠层/短动效                 |
| 突发事件       | 建议       | 增加人物感和荒诞幽默       | 角色半身像与3种表情                                |
| 章节复盘       | 必须       | 形成中程成就感             | 四张章节总结画面                                   |
| 成就           | 必须       | 收藏、炫耀和过程激励       | SVG徽章，ImageGen只做风格探索                      |
| 指标和账本     | 不使用插画 | 保证精确与快速阅读         | SVG图标、CSS图表                                   |
| 最终报告       | 选择性     | 呈现玩家路线               | 本局关键结果图拼贴 + 数据图表                      |

### 8.2 视觉提案的生产约束

LOGO、VI和IP不能由随机生成的整张AI图片直接承担最终比较，因为学生需要比较同一标志在招牌、杯身、头像、外卖包装和遮挡状态下的表现。正确流程是：

1. 用ImageGen探索世界观、材质、门店氛围和IP性格；
2. 将最终LOGO/IP轮廓重绘为可控SVG；
3. 用HTML/CSS/SVG把品牌名和标志投放到统一触点样机；
4. 每套方案保持相同的展示角度、尺寸和信息量；
5. 视觉差异来自真实设计变量：字标/符号/IP、色彩、构图密度、缩小识别和跨触点适配，而不是不同图片质量。

### 8.3 动效规范

- 结果反馈总时长控制在500—900 ms，不能阻止玩家继续操作。
- 现金变化用账本数字滚动与铜钱落下；行动力用印章/脚印消退；时间用日历翻页。
- 场景结果可使用2—3层轻微视差：顾客、柜台、背景；只做位移和透明度。
- 成就先在结果图角落盖章，再展开成就名称；整个过程不超过1.2秒。
- 所有动效提供静态替代；`prefers-reduced-motion`和游戏内“减少动效”同时生效。
- 不建议使用大体积GIF。优先CSS、SVG或短WebM；静态图使用AVIF/WebP。

## 10. 素材技术规范

- 功能图标：SVG，`currentColor`可换色，24 px基准，必须有`aria-hidden`或可访问名称。
- 场景图：AVIF优先、WebP回退；桌面1600 × 900，手机960 × 720。
- 单张场景图建议不超过220 KB，章节大图不超过320 KB。
- 使用`<picture>`和`srcset`，只预加载当前回合；下一回合可在空闲时预取，其余懒加载。
- 图片必须标注焦点位置，例如`--focus-x`、`--focus-y`，避免统一`object-position:center`裁掉关键人物。
- 视觉样机保持SVG/HTML可重排；玩家自填品牌名作为真实文本层叠加，不能烧进位图。
- 低性能设备关闭视差并使用静态图；资源载入失败时显示有叙事意义的占位卡，不能出现空白区域。

## 11. 可访问性与输入规范

- 所有对话框、底部抽屉和侧栏进入时设置初始焦点，关闭后把焦点还给触发按钮。
- 对话框内部必须焦点约束；Esc关闭；手机系统返回先关闭浮层。
- 颜色不能成为支持/风险/未知的唯一提示，必须同时使用形状和文字。
- 支持系统字号放大和游戏内大字号；200%缩放时无水平滚动，主按钮不被遮挡。
- 所有场景图提供描述其“经营意义”的alt，不把纯装饰细节写成冗长说明。
- 动态数值使用非打断式`aria-live="polite"`；连续多个变化合并播报。
- 课程概念弹层不得在玩家操作中途自动抢焦点；首次出现可用非模态提示，玩家主动展开。

## 12. 容易被忽略但必须补上的问题

1. **低端手机性能**：12回合场景和结果图若一次加载，会直接影响开局体验；必须按回合加载。
2. **状态恢复**：刷新后恢复到具体屏幕状态时，要同时恢复滚动/焦点语义，不能回到页面中段让玩家迷路。
3. **方案记忆负担**：五个方案不能只靠反复上下滑；必须有对比盘和“依据数量”。
4. **视觉公平性**：不同视觉方案的样机数量、画幅和精细度必须一致，否则玩家会被表现质量诱导。
5. **图片与因果脱节**：结果图必须至少读取路线类型、结果强度和风险状态三项；只按回合换图不构成反馈。
6. **教学解释过早**：行动前只给足够理解选择的解释，完整理论在结果和报告出现，避免游戏节奏被课堂讲义打断。
7. **投影隐私**：课堂展示模式应在数据层确认匿名，而不是只用CSS隐藏姓名。
8. **文案容器弹性**：不能依赖当前中文字符数固定高度，后续内容修订会造成截断。
9. **失败反馈**：禁用按钮旁必须说明缺什么，并提供可行下一步；不能只变灰。
10. **重玩可辨识性**：重玩应在HUD明确标记“复盘局”，避免学生误以为会覆盖首局。

## 13. 执行阶段与任务拆分

### UIX-01：响应式壳层与设计令牌

建设：新增断点、12列网格、间距/字号/圆角/层级/安全区令牌；建立Compact、Medium、Wide三种布局容器。

主要文件：`apps/web/src/styles.css`、V11布局组件；如组件继续膨胀，应拆出`apps/web/src/v11/ui/`。

验收：320 px至1920 px无横向溢出；安全区生效；大字号不截字；现有游戏流程测试不变。

### UIX-02：紧凑HUD、年度进度与看板

建设：手机HUD压缩为两行；桌面HUD迁入左栏；全年12节点改为可展开时间线；增加动作语义；看板保持顾客/店铺分组。

验收：390 × 844下HUD总高不超过112 px；进入经营现场时首项可执行操作在首屏可见；指标变化由状态事件触发。

### UIX-03：经营现场状态栈

建设：拆成“行动—事实—方案”三个步骤；手机使用单任务屏与底部操作条；桌面使用三栏工作台；刷新恢复当前步骤。

验收：手机完成一轮核心路径不需要在同一长页来回滚动；浏览器返回只返回一个界面层级；桌面主内容不超过两屏完成主要决策。

### UIX-04：事实关系与方案对比盘

建设：事实原位反馈；支持/警告/未知绑定方案；手机2项对比，电脑当前项+钉住项；选择详情统一为一套数据组件。

验收：每条取得的事实可跳到相关方案；方案卡默认不超过两行摘要；所有成本与风险仍完整可访问；禁用状态说明原因。

### UIX-05：视觉比较工作台

建设：把六套视觉方案重绘/整理为统一SVG系统；建立相同的招牌、杯身、外卖袋、头像、遮挡和单色样机；玩家品牌名以文本层实时更新。

验收：字标、符号、IP三类在手机和电脑均有明显区别；所有方案使用同一组样机与尺度；缩小和遮挡测试真实改变预览。

### UIX-06：图标、场景和素材管线

建设：完成必做功能图标、首批10枚成就章、12轮简报图、12张结果骨架、4张章节复盘图；建立AVIF/WebP转换和体积检查脚本。

验收：功能图标不用AI位图；场景图均有桌面/手机裁切；首屏图片不超过预算；断网或图片失败时仍可完成游戏。

### UIX-07：结果、成就与章节反馈

建设：结果画面读取路线、强度和风险状态；增加短动效与减少动效回退；成就盖章；章节复盘形成可收藏画面。

验收：手机结果首屏看见图、现场反应和关键变化；同一回合不同选择至少产生可见差异；成就条件、显示与报告记录一致。

### UIX-08：输入、无障碍、投影与性能验收

建设：焦点栈、Esc/返回、键盘选择、触控尺寸、200%缩放、投影匿名模式、低端机资源策略。

验收：完成第14节全部矩阵；无姓名/学号进入投影DOM、URL和普通日志；所有自动化测试通过后再做80人课堂压力检查。

## 15. 建设优先级

第一优先级是UIX-01至UIX-04，它们直接解决“长问卷、逻辑弱、手机难操作、桌面浪费空间”。第二优先级是UIX-05和UIX-07，它们直接服务课程中的LOGO、VI、IP与经营后果，也是游戏激励感的主要来源。UIX-06中的场景素材可与前端并行制作，但必须先冻结裁切、安全区和命名规范。UIX-08作为发布门，不得用人工印象替代验收矩阵。

完成后的判断标准不是“页面更好看”，而是：玩家在任何设备上都能迅速看懂当前任务、用有限资源取得事实、比较有依据的方案，并从视觉和数值反馈中感受到品牌决策如何进入真实经营。
