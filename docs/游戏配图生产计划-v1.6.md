# 老街品牌局：游戏配图生产计划 v1.6

## 0. 文档定位

本文件替代《视觉资产参考与提示词修订 v1.5》中“仍需用户继续补图”的安排，并承接《游戏界面减法优化与视觉资产建设计划 v1.4》的界面减法原则。

> **提示词修订（2026-08-30）**：具体参考图调用、镜头、空间尺寸、动作、三档状态编辑词和逐图失败判据，以 `docs/游戏配图提示词库-v1.7.md` 为准。v1.7 同时修正了本计划早期版本中资产计数、核心循环引导、结果图选择线索和测试样本量的不严谨表述。

本轮结论是：**现有参考图已经足以冻结地点、门店、经营动作和视觉提案的总体方向，后续缺失的高峰失序、后场库存、酒店供货、配送、IP 物件等参考，由开发方自行检索、整理或生成，不再要求用户继续提供。**

本计划只解决游戏配图及其接入，不借机增加新的页面、入口、卡片或说明模块。图片必须减少文字理解成本、强化选择与后果的联系，而不是把界面变成图片画廊。

## 1. 重新制定后的核心结论

### 1.1 图片不是装饰，必须承担四种游戏职责

按照 MDA 和核心反馈循环，配图只允许承担以下职责：

1. **情境图**：让玩家在读选项前先看懂“现在店里发生了什么”。
2. **决策图**：只有当视觉差异本身就是决策信息时才出现，例如产品、包装、LOGO、IP 和真实触点。
3. **结果图**：选择提交后立刻展示“店里因此变成什么样”，形成明确因果反馈。
4. **成长图**：章节结束时用同一机位展示门店逐步成熟，提供可见的进度与成就感。

不再为每一条普通情报、每一张文字选项卡、每一个随机事件单独配装饰图。首发版事件卡沿用当轮结果图；只有试玩证明某个事件难以理解时，才新增专用事件图，最多四张。

### 1.2 两条视觉生产线并行，但不混用

- **剧情经营线**：写实、自然、略带编辑摄影感的真实经营现场。用于引导、回合简报、执行结果和章节成长。
- **专业设计线**：同机位、同材质、同完成度的产品样机与品牌触点。用于产品、包装、LOGO、VI、IP 的公平比较。

剧情图不承担精确 LOGO 生成；LOGO、IP、玩家自填品牌名和界面文字一律使用 SVG/HTML 叠加。这样既避免伪中文，也能让视觉路线在店招、杯身、头像和小尺寸测试中保持一致。

### 1.3 资产数量控制

正式版本计划生产 **75 张栅格源资产 + 3 套 SVG 视觉系统**；另有 4 张内部锚点图，只用于保持后续生成一致，不随游戏加载。75 是概念源图数量，不包含同一源图导出的手机/桌面裁切文件。

| 类别             |     数量 | 是否进入游戏 | 作用                                                |
| ---------------- | -------: | ------------ | --------------------------------------------------- |
| 世界观与角色锚点 |        4 | 否           | 固定店铺、主角、店员与拍摄基准                      |
| 新手引导         |        5 | 是           | 处境 1 张、胜利目标 1 张、观察—选择—结果短序列 3 张 |
| 十二回合简报     |       12 | 是           | 每轮先看事实，再进入操作                            |
| 十二回合结果状态 |       36 | 是           | 每轮 `stable / strained / crisis` 三档即时反馈      |
| 四章成长         |        4 | 是           | 同机位表现品牌逐步成形                              |
| R03 产品比较     |        5 | 是           | 五种产品路线公平比较                                |
| R04 包装比较     |        5 | 是           | 五种包装/价格结构公平比较                           |
| 视觉触点空白样机 |        5 | 是           | 店招、杯身、包装、头像、单色小票                    |
| R12 IP 功能物件  |        3 | 是           | 杯套收纳、茶包夹、便携杯托                          |
| 正式视觉系统     | 3 套 SVG | 是           | 字标、符号、服务型 IP 三条路线                      |

75 张源图不会同时加载。玩家进入某一轮时只加载该轮简报、当前结果状态和必要的决策图，目标是一次页面跳转不超过约 650 KB 图片传输。

### 2.3 缺失参考由开发方补齐

仍然缺少但不再向用户索要的参考包括：

- 高峰排队、订单堆积、缺货、错单、员工疲劳；
- 清洗区、原料架、库存和外卖打包区；
- 民宿/酒店供货、配送、联名交接；
- 黄山本地茶材、茶汤和小批量制作细节；
- 原创 IP 在功能物件上的尺寸与工艺。

执行方法：

1. 优先检索公开可见的真实零售/服务摄影，只作为内部动作、设备和空间参考；记录 URL、访问日期和用途。
2. 不把检索到的照片直接发行，不复制人物身份、品牌、文字或独特构图。
3. 找不到合适参考时，以已经确认的门店和角色锚点生成中性参考，再从该参考编辑出压力状态。
4. 所有新增参考写入 `docs/visual-references/v1.6-supplement/manifest.md`，明确 `source / role / do-not-copy`。

## 3. 锁定的世界与摄影规则

### 3.1 地点

门店位于现实的屯溪老街当代商业环境中。外部必须看得出石板路、白墙黛瓦、窄街、真实游客与居民；内部是小体量当代茶饮零售店，而不是古装场景、主题乐园、奢侈品商场或空无一物的建筑效果图。

### 3.2 门店材料与颜色

- 暖白透光纸/膜；
- 竹、浅木和深茶褐金属细杆；
- 粗粝浅色石材柜台；
- 奶油白、茶褐、墨黑、灰绿、低饱和橄榄绿；
- 黄绿色只作为少量提示色，不能铺满所有剧情图。

### 3.3 人物

- 主角：二十岁出头的中国年轻品牌经营者，普通、可信、行动明确，不是时尚模特。
- 店员：二十岁出头的中国茶饮店员，穿实用围裙，工作状态自然。
- 顾客：附近居民、通勤者、学生、游客、熟客、合作方和外卖员，依靠动作而非标签区分。
- 皮肤、手部、衣料、杯子接触和设备操作必须真实；禁止过度磨皮、大眼、偶像广告感和塑料皮肤。

### 3.4 构图

- 场景母版使用 3:2；重点保持在中心 60% 安全区。
- 上方 12%、下方 10% 不放不可裁切的关键物件。
- 同一回合结果图固定机位、人物和时间，只改变经营状态和选择进入现场后的物件。
- 图片不生成可读文字、菜单、LOGO、界面、箭头和数据图。

## 4. 图片如何进入游戏循环

### 4.1 新手引导：三屏讲三件事，其中核心循环拆为三帧

| 图片                                                                          | 玩家应在 2 秒内看懂                                    | 建设路径                                                                                        |
| ----------------------------------------------------------------------------- | ------------------------------------------------------ | ----------------------------------------------------------------------------------------------- |
| `onboarding-place`                                                            | 我接手了一间还没定方向的老街茶饮店，街上有不同顾客     | 老街白天外景 + 空白店招 + 主角拿钥匙；参考 01、02、04                                           |
| `onboarding-goal`                                                             | 赢不是只赚最多，而是让顾客认得、店里做得到、经营能继续 | 同一店铺里顾客理解、店员稳定出杯、触点一致同时发生；不做奖杯和排行榜图                          |
| `onboarding-loop-observe`、`onboarding-loop-decide`、`onboarding-loop-result` | 每轮都是先看情况、再选、再看后果                       | 三张连续写实画面由同一屏组合，HTML 只标“先看情况—做决定—看结果”；不要求一张照片同时承载三个时序 |

五张源图仍只占三屏，不得新增说明页。图旁只保留短文和一个继续按钮。

### 4.2 简报图：先建立问题，不提前暗示答案

简报图必须保持中立，同一画面中同时出现机会与限制。玩家不看正文也应知道“这轮在处理顾客、产品、包装、视觉、服务还是增长”。

| 回合           | 画面焦点                                     | 不能误导成                     |
| -------------- | -------------------------------------------- | ------------------------------ |
| R01 客群       | 老街门口，不同人经过、停留、进店             | “游客一定最好”或“居民一定最好” |
| R02 品牌承诺   | 菜单、顾客需求与店员动作是否对得上           | 纯广告文案写作                 |
| R03 产品       | 同一操作台上的产品差异、步骤和设备占用       | 甜品海报或仙气饮品广告         |
| R04 包装与价格 | 带走、堆放、储存、成本和购买犹豫             | 只比包装好不好看               |
| R05 品牌身份   | 字标、符号、IP 如何进入同一组空白触点        | 一张拼贴式“灵感板”             |
| R06 传播触点   | 从门口看到店、理解菜单、点单、拿杯的完整路径 | 单独一张短视频界面             |
| R07 服务       | 高峰柜台的人手、交接、等待和解释             | 夸张灾难或搞笑崩溃             |
| R08 VI 测试    | 店招、杯身、包装、头像、单色小票的真实尺寸   | 只看大幅效果图                 |
| R09 顾客关系   | 熟客、分享、反馈和团队维护工作同时出现       | 抽象社交媒体图标               |
| R10 增长渠道   | 供货箱、联名结构、配送与当前两人团队同框     | “扩张一定更成功”               |
| R11 热度压力   | 排队、订单、库存、员工负荷和被忽略的品牌故事 | 火灾、破产或无厘头闹剧         |
| R12 年度取舍   | 一年留下的产品、包装、顾客、合作与工作记录   | 颁奖礼或完美结局               |

### 4.3 结果图：选择—状态—原因三层合成

当前 `ResultArt` 只按回合显示 SVG 占位，不能表现玩家真正选择的方案。新结果图采用三层结构：

1. **回合状态底图**：同一回合三档 `stable / strained / crisis`，表现店里是否接得住。
2. **玩家选择线索**：R03、R04、R05、R08、R12 在存在具体物件时复用已有产品、包装、视觉或 IP 物件作小型缩略图；R10 只使用现有 UI 风格的单色渠道图标；R01、R02、R06、R07、R09、R11 等抽象选择不额外制造装饰图，继续使用现有选项标题和紧接结果图的一行因果短句。
3. **已选视觉路线**：R08 以后，把玩家选定的字标、符号或 IP SVG 叠到店招、杯套、包装和头像的真实位置。

这样既保留 60 个 `resultArtKey` 的审计语义，又不为 60 个选项生成 60 张互不一致的大照片。`resultArtKey` 继续标识玩家选项，并在存在具体视觉物件时解析到可复用缩略素材；`outcomeState` 决定底图，`routeOverlayKey` 决定视觉 SVG。不存在具体物件时，前端不得为了“有图”而生成无意义的图标或叠层。

三档状态的可见标准：

- `stable`：队伍可控、台面清楚、库存够用、店员仍有精力解释和交接；不是庆功。
- `strained`：仍能营业，但等待变长、台面拥挤、补货减少、员工专注紧张，一名顾客开始犹豫。
- `crisis`：承诺与交付明显不一致；可以出现错拿包装、找不到物料、队伍方向混乱或顾客不理解，但不出现火灾、破产、哭喊和设备爆炸。

### 4.4 章节成长图：固定机位给出成就感

四张图使用同一门店广角锚点逐步编辑：

1. 第一章：客群和主打场景变清楚，但门店仍显稚嫩。
2. 第二章：产品、包装和身份开始形成同一家店的感觉。
3. 第三章：服务动线、熟客关系和反馈进入日常。
4. 第四章：夜间成熟门店能承接一定热度，同时保留现实压力。

章节图只出现在章节复盘顶部，不新增“成长相册”页面。

## 5. 产品、包装、LOGO、VI 与 IP 的配图方案

### 5.1 R03 五种产品

五张图使用完全相同的杯型、机位、背景、杯身留白和完成度，只改变产品本身与制作复杂度：

1. 稳定复购主打茶：结构简单、杯间一致。
2. 复杂出片招牌茶：层次和顶饰明显，但额外工具也必须入镜。
3. 地方茶材轻量产品：真实茶汤和黄山茶叶成为主角。
4. 季节轻仪式茶：只增加一个可持续执行的器具或动作。
5. 模块化菜单：同一茶底形成两至三种清楚变体，仍是一家族。

卡片首屏只显示图、名称和核心取舍；现金、时间、工作量、风险等在选中后进入详情区。图片不能用更华丽的布光替复杂方案拉票。

### 5.2 R04 五种包装与价格结构

同一三分之四俯视机位展示：日常杯、便携礼盒、可回收补充容器、三档价格梯度、饮品点心组合。每张都必须可见真实体积、堆放、提拿、闭合、清洗或库存限制。品牌区域保持空白，再叠加玩家视觉路线。

### 5.3 三条正式视觉路线

视觉比较只展示三套，保证手机上易理解、差异足够大且不存在明显的“标准答案”。

#### A：一笔成街——字标/线性系统

- 核心：清楚可读的中文品牌名 + 一条从屋檐/街巷节奏提炼的连续线。
- 色彩：奶油白、茶褐、低饱和橄榄绿。
- 优势体验：远看能读、缩小不散、容易延展。
- 真实代价：地域故事需要产品与空间继续补充。
- 实现：SVG 字标、连续线和横竖组合规范；不使用图片模型生成中文字。

#### B：山影入杯——独立符号系统

- 核心：原创的杯口、屋檐和茶叶负形组合，不能直接画“山水印章”。
- 色彩：墨黑、黄绿色、米白，参考 12、16 的对比关系但不复制茶壶图形。
- 优势体验：头像、杯套和远距店招更容易形成轮廓记忆。
- 真实代价：地方符号容易同质化，必须通过单色、24 px 和遮挡测试。
- 实现：单色 SVG 主符号 + 字标锁定组合；先做黑白，再决定色彩。

#### C：茶友阿街——服务型 IP 系统

- 核心：一个会帮助点单、取杯、带走和回收的门店服务助手，不是单纯卖萌的吉祥物。
- 色彩：茶褐、奶油白、灰绿；轮廓简洁。
- 固定规则：三种表情、两种动作、一个不可变的核心轮廓；所有版本都必须搭配清楚字标。
- 优势体验：更亲近，容易进入杯套、贴纸和顾客互动。
- 真实代价：需要持续维护角色边界和使用规范。
- 实现：SVG 角色母版和动作部件；照片只生产空白样机与实际使用场景。

### 5.4 五个真实触点

同一套视觉必须在以下场景中被检验：

1. 老街窄店招，远距离和复杂街景；
2. 杯套，被手遮挡约 35%；
3. 外带包装，存在折叠和受潮；
4. 24 px 手机头像；
5. 单色小票/标签。

五个触点使用五张无标识高保真样机作为公共底图，三套 SVG 叠在相同位置。不同路线不得拥有不同材质、布光或样机质量。

### 5.5 R12 三种 IP 功能物件

只比较可小批量生产、能服务老街步行饮用的三个方案：杯套收纳、茶包夹、便携杯托。画面必须显示尺寸、接缝、材料和手持方式；拒绝盲盒、毛绒玩具墙和整套无功能周边。

## 6. 生产提示词结构

正式提示词不再写成一大段风格形容词，而是固定为以下结构：

```text
Use case: photorealistic-natural / product-mockup / precise-object-edit
Asset type: 游戏中的具体位置和用途
Input images: 每张参考图的编号与角色；明确“reference only”或“edit target”
Primary request: 这一张只要表现的事件
Scene/backdrop: 地点、时间、真实空间
Subject: 人物、产品、动作与必须出现的经营线索
Style/medium: 写实编辑摄影或高保真样机摄影
Composition/framing: 镜头、机位、安全裁切区
Lighting/mood: 自然光/暖纸灯及情绪
Color palette: 奶油白、茶褐、墨黑、灰绿与少量黄绿
Materials/textures: 纸、竹、木、浅石、真实设备和使用痕迹
Constraints: 必须保持的角色、机位、物件和公平比较条件
Avoid: 伪中文、现成品牌、水印、夸张美颜、卡通占位、无关装饰
```

生产规则：

- 新场景用“生成”；同回合三档结果用批准后的母场景做“编辑”，每次只改经营状态。
- 人物、空间和产品母版批准后才进入批量；不能每一轮重新设计人物和店铺。
- 参考图必须在提示词里逐张标注角色，不能笼统写“参考所有图片”。
- 需要透明前景时明确要求真实透明背景并保留 alpha。
- 图片模型不负责最终中文、品牌名、LOGO 或 UI；准确内容由代码叠加。
- 每次迭代只修一个问题，例如“只调整队伍长度，保持其余不变”。
- 每次生成最多调用 4 张真正相关的参考图；分别标注地点、动作、材料和构图角色，避免多套案例互相污染。

逐图完整提示词见 `docs/游戏配图提示词库-v1.7.md`。

### 7.2 命名示例

- `onboarding-place.webp`
- `briefing-r03-product.webp`
- `result-r07-stable.webp`
- `result-r07-strained.webp`
- `result-r07-crisis.webp`

- `package-r04-gift-box.webp`
- `touchpoint-storefront.webp`
- `visual-v-line.svg`
- `chapter-03-service.webp`

### 7.3 输出规格

- 审核母版：1536 × 1024，3:2。
- 桌面场景输出：1440 × 960 WebP。
- 手机场景输出：960 × 720 WebP；必要时为竖屏重点场景单独裁切，而不是依靠浏览器硬裁。
- 产品与包装：1200 × 1200 WebP，统一正方形卡片。
- 透明局部素材：WebP/PNG alpha；正式 LOGO/IP 使用 SVG。
- 简报图目标不超过 220 KB；结果图不超过 260 KB；单个触点样机不超过 180 KB。
- 同时保留手机和桌面衍生图后，部署目录目标不超过 28 MB；当前回合初次图片传输仍不超过 650 KB。

mobileCropFocus
alt
filePath
fileBytes

## 8. 前端接入方案

### 8.1 `SceneArt`

将当前固定引用 `scene-atlas.svg#...` 的方式改为清单驱动的 `<picture>`：

- 优先加载手机/桌面 WebP；
- `object-position` 来自资产清单；
- 图片失败时回退到统一 SVG 占位；
- 新手引导与当前简报可 eager，下一轮预取，其余 lazy；
- `alt` 描述当前经营事实，不重复页面标题。

### 8.2 `ResultArt`

改为三层：

```text
状态底图：roundId + outcomeState
        ↓
选择线索：resultArtKey（产品、包装、渠道或服务物件）
        ↓
视觉叠层：routeOverlayKey（R08 后有效）
```

`crisis` 只是代码状态名，玩家界面仍使用“明显失配/现场没接住”等自然中文，不出现后台枚举值。

### 8.3 视觉比较

三套视觉卡直接展示真实“店招 + 杯套 + 头像”缩略组合。选择后，右侧/下方详情只显示一个当前触点；玩家用标签切换店招、杯身、头像。单色、24 px、遮挡测试通过 CSS/SVG 改变同一资产，不再生成三套伪造截图。

手机端采用纵向：三张方案卡横向滑动，当前触点预览固定在下方；不使用左右双栏，不要求横屏。

### 8.4 章节图

章节复盘顶部只展示一张成长图，下面继续使用现有指标和复盘内容。禁止再增加轮播、相册或解锁页。

## 9. 分阶段执行计划

### A16-00：参考冻结与来源清单

建设：完成两批用户参考的编号、用途、禁用项和重复项；自行补齐后场、压力和渠道参考。

验收：每张参考都有来源角色；发行目录中没有用户原图、第三方水印或真实品牌素材。

### A16-01：锚点小样

建设：生成门店内外空间、主角、店员 4 个锚点，每个 2–3 个候选；先检查真实尺度、人物气质和材料，不做批量。

验收：固定门店结构、角色身份、围裙、镜头和色彩；至少在 390 × 844 手机截图中仍能看清动作。

### A16-02：首批发布门

建设：制作 R01 简报、R01 三档结果、R03 五个产品、三套视觉路线和五个触点样机。

验收：

- 三档结果两秒内能区分；
- 产品五选一不存在明显画质偏袒；
- 三套视觉路线在 24 px、单色、遮挡 35% 后仍呈现真实差异；
- 所有文字由 SVG/HTML 产生。

未通过时只修改首批小样，不进入批量生产。

### A16-03：引导与十二回合简报

建设：完成 5 张引导源图并组合为 3 屏，以及 12 张简报；按回合检查画面是否中立、是否建立问题。

验收：随机隐藏正文，让至少 5 名测试者判断回合主题；至少 4/5 能区分客群、产品、视觉、服务和增长。

### A16-04：专业决策资产

建设：完成五种包装、三种 IP 功能物件，以及视觉系统在五个触点的代码合成。

验收：产品/包装/视觉均为同机位、同大小、同完成度；LOGO 与 IP 有实际图形，不再是颜色块或几何占位。

### A16-05：高影响结果图

建设：优先完成 R01、R03、R05、R08、R11、R12 的 18 张状态图并接入。

验收：玩家的选择、经营压力和视觉路线能在同一结果页相互对应；结果图不能与选择标题矛盾。

### A16-06：其余结果与章节成长

建设：完成 R02、R04、R06、R07、R09、R10 的 18 张状态图和 4 张章节图。

验收：12 回合不再落回同一组通用占位；四章固定机位、空间和人物连续。

### A16-07：响应式接入与性能

建设：实现清单驱动加载、移动裁切、失败回退、下一轮预取和旧 `scene-atlas.svg` 的非破坏性 fallback。

验收：无图片 404；离线刷新可读；当前回合图片传输不超过目标；360–430 px 手机无需横向滚动。

### A16-08：完整视觉验收

建设：运行自动检查与人工试玩，对照所有资产键和状态。

验收：通过下节全部测试后才能把旧 SVG 占位降级为 fallback。

## 10. 测试与验收清单

### 10.1 自动测试

1. `asset-manifest` 中所有 `imageKey`、`resultArtKey` 和视觉路线文件存在。
2. 所有正式文件可解码，尺寸、格式和文件大小符合预算。
3. 每个回合都有 `stable / strained / crisis` 三档底图。
4. `SceneArt` 加载失败会显示 fallback，不出现白屏或无限等待。
5. `ResultArt` 根据 `roundId + outcomeState + resultArtKey + routeOverlayKey` 组合正确。
6. 玩家自填品牌名只进入 HTML/SVG 文本层，不进入图片 URL、文件名或生成请求。
7. 截图测试覆盖 360 × 800、390 × 844、412 × 915、768 × 1024、1440 × 900。
8. 网络测试确认首屏与当前回合没有图片 404，且不会一次加载全部 75 张源图及其衍生文件。
9. 执行项目既有 `pnpm lint`、`pnpm typecheck`、`pnpm test`，再运行 Web E2E。

### 10.2 人工视觉检查

- 老街是否像现实商业街，而不是古装景区概念图；
- 同一人物、门店、杯型和空间是否连续；
- 手、杯盖、吸管、设备和台面操作是否合理；
- 图片中是否出现伪中文、第三方 LOGO、水印或可识别品牌；
- 三套视觉路线是否明显不同但完成度相当；
- `strained` 和 `crisis` 是否是现实压力，不是灾难喜剧；
- 结果图能否在两秒内回答“发生了什么”和“为什么与我的选择有关”；
- 手机裁切是否保留关键人物、产品和经营线索；
- 图片是否减少文字负担，而不是制造新的阅读任务。

## 11. 明确不做的内容

- 不把用户提供的案例图直接放进游戏。
- 不复制参考品牌、LOGO、字体设计、IP、中文文案或版式。
- 不为每个情报和每个事件增加一张装饰图。
- 不使用 AI 生成的中文标志作为正式 LOGO。
- 不新增横屏要求、视觉相册、图片商店、收集页或额外导航。
- 不让图片承担规则解释；现金、行动力、时间和指标仍由清楚的 UI 文本负责。
- 不在运行时调用图片 API；所有正式素材在发布前生成、审核、压缩并随静态资源发布。

## 12. 最终验收定义

配图升级完成不是“图片数量够了”，而是同时满足：

1. 玩家在简报图中先看见问题，再做选择；
2. 产品、包装、LOGO、VI、IP 有可公平比较的真实示意；
3. 提交选择后，结果图立即呈现相应经营状态和选择痕迹；
4. R08 以后，玩家选择的视觉路线持续进入门店与包装，而不是只出现一次；
5. 四章成长图让玩家看见门店逐步成形；
6. 手机端没有因为图片增加新的长页面和交互负担；
7. 所有资产可追溯、可替换、可测试，不再依赖一个通用 `scene-atlas.svg` 冒充全部内容。
